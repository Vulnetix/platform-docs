## Overview

VNX-484 maps to [CWE-484: Omitted Break Statement in Switch](https://cwe.mitre.org/data/definitions/484.html). It reports a `case` (or `default`) label whose own statements run on into the next label of the same switch because the body does not end in `break`, `return`, `throw`, `continue`, `goto`, `yield` or a call that never returns.

## Why this matters

A forgotten `break` runs the next case's code as well: a permission granted for one role is also applied for the role below it, a state machine skips a state, or a buffer is written twice. The compiler accepts it, and the code reads correctly at a glance.

## What gets flagged

```c
switch (cmd) {
case 2:                 // FLAGGED: runs on into case 3
    *state = 20;
    log_cmd(cmd);
case 3:
    *state = 30;
    break;
}
```

```java
switch (tier) {
    case GOLD:          // FLAGGED
        pct = 20;
    case SILVER:
        pct = 10;
        break;
}
```

Not flagged: `case 1: case 2:` stacked labels, `/* fall through */` or `[[fallthrough]];` before the next label, `case X ->` arrow labels, and bodies ending in `return`, `throw`, `exit()` or `abort()`.

## Remediation

1. Add the missing `break` (or `return`) at the end of the case body.
2. If the fall-through is intended, say so: `[[fallthrough]];` in C++17/C23, `__attribute__((fallthrough));` in GCC/Clang C, or a `// fall through` comment in Java, and enable `-Wimplicit-fallthrough` / `-Xlint:fallthrough`.
3. In Java 14+, prefer arrow labels (`case X ->`), which cannot fall through.
