## Overview

VNX-780 maps to [CWE-780: Use of RSA Algorithm without OAEP](https://cwe.mitre.org/data/definitions/780.html). It reports RSA encryption and decryption that use PKCS#1 v1.5 padding or no padding:

- Java/Kotlin `Cipher.getInstance("RSA")`, `"RSA/ECB/PKCS1Padding"`, `"RSA/NONE/NoPadding"` (inline, on the next line or through a constant), BouncyCastle `new PKCS1Encoding(...)`
- Python `padding.PKCS1v15()` passed to `encrypt()`/`decrypt()`, PyCryptodome `Crypto.Cipher.PKCS1_v1_5.new()`, python-rsa `rsa.encrypt()`/`rsa.decrypt()`
- Node.js `publicEncrypt`/`privateDecrypt` with `RSA_PKCS1_PADDING` or `RSA_NO_PADDING`, node-rsa `encryptionScheme: 'pkcs1'`, `new JSEncrypt()`
- Go `rsa.EncryptPKCS1v15`, `rsa.DecryptPKCS1v15`, `rsa.DecryptPKCS1v15SessionKey`
- PHP `openssl_public_encrypt`/`openssl_private_decrypt` with no padding argument or a PKCS1/no-padding constant, phpseclib PKCS1 encryption mode
- Ruby `public_encrypt`/`private_decrypt` with no padding argument or `PKCS1_PADDING`/`NO_PADDING`
- C# `rsa.Encrypt(data, false)`, `RSAEncryptionPadding.Pkcs1`

Not reported: OAEP, PKCS#1 v1.5 signatures (`sign`/`verify`, `SignPKCS1v15`, `RSASignaturePadding.Pkcs1`), Node `publicEncrypt` with a bare key (its default is OAEP), and transformations passed in as parameters. Java `Cipher.getInstance` is also covered by VNX-JAVA-018.

## Why This Matters

A service that decrypts PKCS#1 v1.5 ciphertext and reveals, through an error or timing, whether the padding was valid is a padding oracle: Bleichenbacher's attack recovers the plaintext (often a session key) with adaptive queries. Unpadded RSA is deterministic and malleable.

## What Gets Flagged

```java
Cipher c = Cipher.getInstance("RSA/ECB/PKCS1Padding");          // FLAGGED
```

```python
return public_key.encrypt(message, padding.PKCS1v15())           # FLAGGED
```

```go
return rsa.EncryptPKCS1v15(rand.Reader, pub, msg)                // FLAGGED
```

Not flagged:

```go
return rsa.EncryptOAEP(sha256.New(), rand.Reader, pub, msg, nil)
```

## Remediation

1. Use OAEP with SHA-256: `RSA/ECB/OAEPWithSHA-256AndMGF1Padding`, `padding.OAEP(...)`, `rsa.EncryptOAEP`, `RSA_PKCS1_OAEP_PADDING`, `OPENSSL_PKCS1_OAEP_PADDING`, `RSAEncryptionPadding.OaepSHA256`.
2. Prefer a hybrid scheme (RSA-OAEP or ECDH to wrap an AES-GCM key) for anything larger than a key.
