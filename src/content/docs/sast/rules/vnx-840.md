## Overview

VNX-840 maps to [CWE-840: Business Logic Errors](https://cwe.mitre.org/data/definitions/840.html). CWE-840 is a category; this rule reports its most concrete, statically recognisable form: the server lets the client decide how much money moves.

A finding is a request field named like money (`amount`, `price`, `total`, `subtotal`, `discount`, `cost`, `fee`, with suffixes such as `_percent` or `_cents`) that reaches, directly or through one assignment:

- an `amount` / `unit_amount` / `total` / `subtotal` / `discount` key or keyword argument, such as a payment-provider call (`stripe.paymentIntents.create({ amount })`, `stripe.Charge.create(amount=...)`);
- an assignment to an order's `.total`, `.amount`, `.subtotal`, `.discount`, or an account's `.balance` (including `+=` and `-=`);
- a total computed by arithmetic on the client value.

## Why This Matters

If the client sends the price, the client sets the price. A tampered request pays one cent, applies a 100% discount, or transfers a negative amount that credits the sender.

## What Gets Flagged

```javascript
// FLAGGED: the client chooses what it is charged
const intent = await stripe.paymentIntents.create({ amount: req.body.amount, currency: 'usd' });

// FLAGGED: total reduced by a client-supplied discount
const total = cart.subtotal - req.body.discount;
```

```python
# FLAGGED: balance moved by an unchecked client amount (a negative value reverses it)
amount = int(request.form["amount"])
src.balance -= amount
```

Not flagged: a price looked up on the server (`product.price_cents * qty`), request identifiers and codes (`productId`, `coupon_code`, `quantity`), a client value compared with a server value or range-checked in an `if` before use, an admin catalogue edit of `product.price`, and non-payment code that happens to use a `total` keyword.

## Remediation

1. Compute amounts on the server from the order, catalogue and coupon records; accept only identifiers from the client.
2. Where the client must send an amount (a donation, a partial refund), validate it: positive, within the allowed range, and no larger than what is owed or paid.
3. Never apply a balance change before checking sign and sufficient funds.
