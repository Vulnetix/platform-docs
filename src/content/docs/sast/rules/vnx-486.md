## Overview

VNX-486 maps to [CWE-486: Comparison of Classes by Name](https://cwe.mitre.org/data/definitions/486.html). It reports code that decides what type an object is by comparing the class's name string instead of the class itself.

## Why This Matters

A name is not an identity. Two classes loaded by different class loaders, a class in another package or module with the same simple name, or a plugin an attacker controls can all carry the name the check expects. When the comparison guards trust ("is this the trusted plugin?", "is this an admin principal?"), the wrong type passes.

## What Gets Flagged

```java
if (plugin.getClass().getName().equals("com.acme.plugins.TrustedPlugin")) { ... }  // FLAGGED
if ("AdminHandler".equals(h.getClass().getSimpleName())) { ... }                 // FLAGGED
```

```csharp
if (caller.GetType().Name == "TrustedCaller") return true;   // FLAGGED
```

```python
if type(principal).__name__ == "AdminUser":   # FLAGGED
    return True
```

Not flagged: `plugin instanceof TrustedPlugin`, `plugin.getClass() == CorePlugin.class`, `caller is TrustedCaller`, `isinstance(principal, AdminUser)`, and reading a class name for a log line.

## Remediation

1. Compare types, not strings: `instanceof` / `Class.isAssignableFrom` / `getClass() == Foo.class` in Java, `is` / `typeof(Foo)` in C#, `isinstance` or `type(x) is Foo` in Python.
2. Where a name must come from configuration, resolve it once through a trusted class loader and compare the resulting class object.
