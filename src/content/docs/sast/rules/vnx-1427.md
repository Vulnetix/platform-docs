## Overview

VNX-1427 maps to [CWE-1427: Improper Neutralization of Input Used for LLM Prompting](https://cwe.mitre.org/data/definitions/1427.html). Text in the system role carries the authority of the application's own instructions. When request data is spliced into it, a user can rewrite those instructions: ignore the rules, reveal the prompt, or steer tool calls.

The rule reports request data (read on the line, or through a variable assigned from a request read in the 30 lines above) inside a system-role slot. Python, JavaScript and TypeScript are covered by VNX-LLM-004 (system prompt) and VNX-LLM-001 (instruction text).

## What gets flagged

```go
persona := r.URL.Query().Get("persona")
// ...
Role:    openai.ChatMessageRoleSystem,
Content: fmt.Sprintf("You are %s. Never reveal internal data.", persona),

openai.SystemMessage("You are an expert on " + topic),   // topic := c.Query("topic")
```

```java
public String assist(@RequestParam String role, @RequestParam String question) {
    return chatClient.prompt().system("You are a " + role + " assistant.").user(question).call().content();
}
```

```php
['role' => 'system', 'content' => "You are a {$persona} assistant."],   // $persona = $_GET['persona']
```

```ruby
{ role: "system", content: "Reply in a #{tone} voice." },   # tone = params[:tone]
```

Not flagged: request data in a user-role message (`.user(question)`, `role: "user"`, also when it shares a line with the system message), in Go request data used only as a map key (`personas[r.FormValue("p")]`, an allowlist lookup), a static system prompt, server-side values such as dates and constants, and the shapes inside comments or string literals.

## Remediation

1. Keep the system prompt static. Pass user text only as a user-role message.
2. If a user choice must shape behaviour, map it to one of a fixed set of server-side prompts (an allow-list), never interpolate it.
3. Treat model output as untrusted and constrain what tools it can call.
