## Overview

VNX-1092 maps to [CWE-1092: Use of Same Invokable Control Element in Multiple Architectural Layers](https://cwe.mitre.org/data/definitions/1092.html). It reports Python data-layer modules that use the presentation layer's request/response machinery: the request object, the session, redirects and response builders. A data-layer module is `models.py`, `repository.py`, `dao.py`, or any file in a `models/`, `repository/`, `repositories/`, `dao/` or `dal/` package.

## Why This Matters

When a model reads `request.args` itself, the same control element runs in both the view and the data layer. Data access then depends on whichever HTTP request happens to be active, the model cannot be used from a job or a CLI, and validation the view performs can be bypassed by a model method that reads the raw request directly.

Reported: imports of `request`, `session`, `render_template`, `redirect`, `make_response`, `flash` or `abort` from Flask, anything from `django.http` or `django.shortcuts`, `Request` from FastAPI, Starlette or DRF, and reads such as `request.form`, `request.GET`, `request.json`, `session[...]` when `session` is imported from Flask, and the same reads through a parameter annotated `: Request` (`req.json`).

Not reported: `flask.g` and `current_app` (the documented way to share a connection), `django.urls.reverse` for `get_absolute_url`, view and service modules, test files and comments.

## What Gets Flagged

```python
# shop/models.py
from flask import request, g                        # FLAGGED

class Order(Base):
    @classmethod
    def from_form(cls):
        note = request.form.get("note", "")         # FLAGGED
        return cls(note=note)
```

## Remediation

1. Read and validate request data in the view, and pass plain values to the model (`Order.create(note=note)`).
2. Raise domain exceptions from the data layer and translate them to HTTP responses in the view.
3. For a confirmed false positive, add a `# vulnetix-ignore: VNX-1092` comment on the line.
