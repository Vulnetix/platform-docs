## Overview

VNX-935 maps to [CWE-935: OWASP Top Ten 2013 Category A7 - Missing Function Level Access Control](https://cwe.mitre.org/data/definitions/935.html). The category has no code shape of its own. This rule reports the one only an annotation can produce: a Spring or JAX-RS handler, in Java or Kotlin, mapped to a path that names an administrative function (`/admin`, `/administrator`, `/superadmin`, `/sysadmin`, `/management`, `/manage`, `/backoffice`, `/staff`) and annotated `@PermitAll`, `@PreAuthorize("permitAll()")`, `@Secured("IS_AUTHENTICATED_ANONYMOUSLY")` or `@AnonymousAllowed`, which opens it to every caller.

## What Gets Flagged

```java
@GetMapping("/admin/users")
@PreAuthorize("permitAll()")                               // flagged: opens an admin function to everyone
public List<User> list() { ... }
```

Not flagged: Spring handlers without such an annotation (Spring Security is configured centrally; VNX-931 judges that configuration), handlers that require a role (`@PreAuthorize("hasRole('ADMIN')")`), non-administrative paths, test files, comments and strings. Authorization enforced in another module (a gateway, a global filter) is not visible to the rule.

Reported by other rules, so one route is one finding:

- An administrative Flask, FastAPI or Quart route with nothing in front of it is reported by [VNX-306](/sast/rules/vnx-306/).
- An administrative Express, Koa, Fastify or Go route with nothing in front of it is reported by [VNX-425](/sast/rules/vnx-425/).

## Remediation

Require the administrator role on the server for every administrative function, and never open one with `permitAll`:

```java
@GetMapping("/admin/users")
@PreAuthorize("hasRole('ADMIN')")
public List<User> list() { ... }
```
