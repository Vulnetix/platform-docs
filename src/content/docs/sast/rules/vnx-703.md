## Overview

VNX-703 maps to [CWE-703: Improper Check or Handling of Exceptional Conditions](https://cwe.mitre.org/data/definitions/703.html). An empty `Optional` is an expected outcome: no row has this id, no element matches the filter. `get()` turns that outcome into an unchecked `NoSuchElementException`, so a request for an unknown id becomes an HTTP 500 with a stack trace instead of a 404.

The rule reports, in production `.java` files:

- Spring Data `findById(...).get()`;
- `findFirst().get()` and `findAny().get()`, including `.get()` on the next line of a split chain;
- stream `max(...)`/`min(...)` and `reduce(X::y)` followed by `.get()`;
- `IntStream`/`LongStream`/`DoubleStream` `max()`/`min()`/`average()`/`findFirst()` followed by `getAsInt`/`getAsLong`/`getAsDouble`;
- `Optional.ofNullable(...).get()`;
- a variable declared `Optional<T>` (or `OptionalInt`/`OptionalLong`/`OptionalDouble`) whose `get()` is called within the next 15 lines with no `isPresent()`, `isEmpty()`, `ifPresent()` or null test of it in between or on the same line.

Not reported: `orElse`, `orElseGet`, `orElseThrow`, `ifPresent`, a presence test before the `get()`, `Map.get`, `Future.get`, `List.get`, `Collections.max(...).get(...)`, test files, comments and string literals. Optionals passed between methods or stored in fields are not followed.

## What gets flagged

```java
return orders.findById(id).get();                                   // FLAGGED
return list.stream().max(Comparator.comparing(Order::total)).get(); // FLAGGED

Optional<Account> account = repo.findByLogin(login);
return account.get().getEmail();                                    // FLAGGED
```

## What is not flagged

```java
return orders.findById(id).orElseThrow(() -> new NotFoundException(id));

Optional<Account> a = repo.findByLogin(login);
if (a.isEmpty()) {
    return "";
}
return a.get().getName();
```

## Remediation

1. Use `orElseThrow(() -> new NotFoundException(...))` so the absent case maps to a deliberate error (and a 404).
2. Use `orElse`/`orElseGet` when a default is meaningful, or `ifPresent` for side effects.

## Suppressing this rule

Put a `nosec` comment on the line, or on line 1 to cover the whole file. Use the comment marker of the file's language (`#`, `//`, `--` or `;`):

```text
# nosec vnx-703
// nosec vnx-703
```

Or record an ignore rule: `vulnetix ignore add --rule vnx-703 --reason "..."`. See [Suppressing findings](/sast/guides/suppressing-findings/).
