## Overview

VNX-584 maps to [CWE-584: Return Inside Finally Block](https://cwe.mitre.org/data/definitions/584.html). It reports a `return` inside a `finally` block at any depth (inside an `if`, a nested `try`), including the one-line form `finally { return x; }`. The block is bounded by brace depth, or indentation for Python, within 80 lines.

## Why This Matters

A `return` in `finally` completes the whole `try` statement normally. Any exception thrown by the `try` or `catch` block is silently dropped, and the `try` block's own return value is replaced. Failures such as a failed write, an authorisation error or a parse error then look like success to the caller.

## What Gets Flagged

```java
} finally {
    stream.close();
    return -1;
}
```

```ts
} finally { return undefined; }
```

```python
finally:
    if cache is not None:
        return cache
```

Not flagged: a return after the `finally` block closes, a return in the `try` or `catch` block, a return inside a lambda, arrow function, anonymous class or nested `def` opened in the `finally` block, comments and strings.

## Remediation

1. Move the `return` after the `try`/`finally` statement, or into the `try` block.
2. Keep `finally` for cleanup only; if cleanup can fail, record that failure without replacing the original exception (for example with `addSuppressed`).
