## Overview

VNX-594 maps to [CWE-594: J2EE Framework: Saving Unserializable Objects to Disk](https://cwe.mitre.org/data/definitions/594.html). The container may write some objects to disk or move them between nodes: it passivates session-scoped beans, replicates sessions across a cluster, and detaches entities to send them to remote callers. Those objects must be `Serializable`.

The rule reports the class declaration of a JPA `@Entity`, `@Embeddable` or `@MappedSuperclass` (javax or jakarta), or of a CDI `@SessionScoped` or `@ConversationScoped` bean, when the declaration (which may span lines) neither implements `Serializable` or `Externalizable` nor extends another class.

It does not report classes that implement `Serializable`, `Externalizable` or a Spring Security interface that extends it (`UserDetails`, `GrantedAuthority`, `Authentication`), classes that extend a superclass (which may be Serializable; superclasses are not resolved), interfaces, records and enums, lookalike annotations such as `@EntityListeners`, or annotations in comments.

## Why this matters

When serialisation fails the container either throws at passivation or replication time, under load and in production, or drops the object's state. A user's cart or wizard state disappears on fail-over, and a detached entity cannot be returned to a remote client.

## What gets flagged

```java
@Entity
@Table(name = "customers")
public class Customer {              // FLAGGED
    @Id private Long id;
}

@SessionScoped
public class CartBean implements Cloneable {   // FLAGGED

// NOT FLAGGED
@Entity
public class Product implements Serializable {
    private static final long serialVersionUID = 1L;
}

@Entity
public class Invoice extends BaseEntity { }    // superclass not resolved
```

## Remediation

1. Implement `java.io.Serializable` on the class and declare a `serialVersionUID`.
2. Mark fields that cannot be serialised (connections, streams, loggers) `transient` and restore them after deserialisation.
