## Overview

VNX-548 maps to [CWE-548: Exposure of Information Through Directory Listing](https://cwe.mitre.org/data/definitions/548.html). A server that answers a request for a directory with a list of its files lets anyone enumerate backups, logs, uploads and keys that were never linked. The rule reports:

- JavaScript/TypeScript: a `serveIndex(...)` call (the serve-index middleware), and `@fastify/static` registered with `list: true`;
- Python: Django's static `serve` view with `"show_indexes": True` or `static(..., show_indexes=True)`, aiohttp `add_static(..., show_index=True)`, Flask-AutoIndex `AutoIndex(app, ...)`;
- Java: a Tomcat `listings` or Jetty `dirAllowed` init-param set to `true` in `web.xml`, Jetty `setDirectoriesListed(true)` and `setInitParameter("dirAllowed", "true")`;
- nginx `autoindex on;` (also inside a one-line `location` block) and Apache `Options Indexes` / `Options +Indexes` / `Options All` in `.conf` files, `sites-available`/`sites-enabled` and `.htaccess`.

## What gets flagged

```javascript
app.use('/ftp', express.static('ftp'), serveIndex('ftp', { icons: true }));  // FLAGGED
```

```nginx
location /downloads/ {
    autoindex on;   # FLAGGED
}
```

## What is not flagged

- Importing serve-index without calling it, and file servers that do not list directories (`express.static`).
- The settings switched off: `autoindex off`, `Options -Indexes`, `listings` false, `show_indexes: False`, `setDirectoriesListed(false)`.
- Commented-out directives, string literals and test files.

Go's `http.FileServer` lists any directory without an `index.html`; it is not reported because nearly every use serves a directory of public assets on purpose.

## Remediation

Turn directory listing off and serve only the files that are meant to be public. Put downloadable files behind an explicit index page or an authenticated handler.
