## Overview

VNX-329 maps to [CWE-329: Generation of Predictable IV with CBC Mode](https://cwe.mitre.org/data/definitions/329.html). It reports an IV or nonce that is predictable because it is derived from the encryption key, drawn from a non-cryptographic generator, or built from the clock.

## Why this matters

A predictable CBC IV allows chosen-plaintext attacks (BEAST is the famous one). Using the key as the IV is worse: an attacker who can get one chosen ciphertext decrypted recovers the key itself.

## What gets flagged

```python
# FLAGGED: the IV is the key
AES.new(key, AES.MODE_CBC, key)
iv = key[:16]
# FLAGGED: the IV comes from the random module
iv = random.randbytes(16)
```

```java
// FLAGGED
new IvParameterSpec(keyBytes)
byte[] ivBytes = Arrays.copyOf(secretKey, 16);
rnd.nextBytes(iv);   // rnd is a java.util.Random
```

```go
// FLAGGED
cipher.NewCBCEncrypter(block, key[:aes.BlockSize])
rand.Read(iv)        // math/rand
```

```javascript
// FLAGGED
crypto.createCipheriv('aes-256-cbc', key, key.slice(0, 16));
```

## What is not flagged

- IVs from `os.urandom`, `secrets`, `get_random_bytes`, `SecureRandom`, `crypto/rand`, `randomBytes` or `getRandomValues`.
- IVs read from the ciphertext (`blob[:16]`).
- Constant IVs, which [VNX-CRYPTO-010](/sast/rules/vnx-crypto-010/) and [VNX-JAVA-020](/sast/rules/vnx-java-020/) report.
- Names that only contain the letters (`keys`, `keyword`, `keystore`), comments, string literals and test files.

## Remediation

Generate a fresh IV for every message from a CSPRNG and send it with the ciphertext, or use an AEAD mode with a random or counter nonce that is never reused under the same key.
