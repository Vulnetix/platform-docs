## Overview

VNX-367 maps to [CWE-367: Time-of-check Time-of-use (TOCTOU) Race Condition](https://cwe.mitre.org/data/definitions/367.html). A file is checked by name and then opened or changed by the same name within ten lines, in C or C++, so another process can swap the file (typically for a symlink) between the check and the use. Reported: access(), eaccess() or euidaccess() on a path followed by any open, open64, fopen, freopen, creat, chmod, chown, lchown, truncate or exec* of that path (the access-then-open setuid race); and stat(), lstat(), stat64() or lstat64() on a path followed by a write or permission change on it: open with O_WRONLY/O_RDWR/O_CREAT/O_TRUNC/O_APPEND, fopen with a w/a/+ mode, creat, chmod, chown, lchown or truncate. The same check and use on one line count. The path may be a variable, a member, a std::string's c_str() or a literal. Not reported: open with O_EXCL or O_NOFOLLOW, a read after a stat, fstat/fchmod on a descriptor (the safe form), a check and a use on different paths, comments and string literals.

## Why this matters

`access()` and `stat()` look a path up; the `open()` that follows looks it up again. Between the two another process can replace the file with a symbolic link, so a setuid program that checked the real user's permission writes to a file the user could not.

## What gets flagged

```c
/* FLAGGED: access() check, then open of the same path */
if (access(path, W_OK) != 0)
	return -1;
int fd = open(path, O_WRONLY | O_APPEND);
```

```c
/* FLAGGED: stat(), then a write-mode fopen */
if (stat(cfg, &st) == 0 && st.st_uid == getuid())
	fp = fopen(cfg, "w");
```

## What is not flagged

```c
int fd = open(path, O_WRONLY | O_CREAT | O_EXCL | O_NOFOLLOW, 0600);
fstat(fd, &st);   /* check the descriptor you opened */
```

A read after a `stat()` (the write flags are read from that call's own text, so a later `open(dst, O_CREAT ...)` does not count), `fstat`/`fchmod` on a descriptor, a check and a use on different paths or in different functions, comments and string literals are not reported.

## Remediation

1. Open first, then check the descriptor with `fstat`, and change it with `fchmod`/`fchown`.
2. Use `O_EXCL` and `O_NOFOLLOW`; in a setuid program drop to the real user's IDs before opening instead of calling `access()`.
