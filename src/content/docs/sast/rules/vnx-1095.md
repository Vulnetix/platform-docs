## Overview

VNX-1095 maps to [CWE-1095: Loop Condition Value Update within the Loop](https://cwe.mitre.org/data/definitions/1095.html). The collection a `for` loop iterates over is its loop condition; changing it inside the body changes the condition while the loop runs.

- **Python:** inside `for x in items:` (or `items.keys()`/`values()`/`items()`), a call to `items.remove/pop/popitem/insert/clear/update/setdefault/add/discard` or `del items[...]`.
- **Java:** inside `for (T x : items)` (or `items.entrySet()`/`keySet()`/`values()`), a call to `items.remove/add/addAll/removeAll/retainAll/removeIf/clear/put/putAll`.

## Why this matters

Removing from a Python list while iterating skips the element after each removal, so an "expire every stale session" loop leaves some stale sessions alive. Changing a dict or set raises `RuntimeError`. In Java the iterator throws `ConcurrentModificationException` on its next step, which turns a clean-up path into a crash.

Not reported: iteration over a copy (`list(items)`, `items[:]`, `items.copy()`, `sorted(items)`, `new ArrayList<>(items)`), a mutation followed directly by `break` or `return`, `list.append`/`extend` (the worklist idiom), `Iterator.remove()`, Java files using concurrent or copy-on-write collections, and comments.

## What gets flagged

```python
for s in sessions:
    if s.expires_at < now:
        sessions.remove(s)          # FLAGGED
```

```java
for (Map.Entry<String, Entry> e : entries.entrySet()) {
    if (e.getValue().size() > limit) {
        entries.remove(e.getKey());     // FLAGGED
    }
}
```

## Remediation

1. Iterate over a copy, or build a new collection (`[s for s in sessions if s.expires_at >= now]`).
2. In Java use `Iterator.remove()`, `removeIf(...)` or `entrySet().removeIf(...)`.
3. For a confirmed false positive, add a `vulnetix-ignore: VNX-1095` comment on the line.
