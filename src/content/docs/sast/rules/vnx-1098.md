## Overview

VNX-1098 maps to [CWE-1098: Data Element containing Pointer Item without Proper Copy Control Element](https://cwe.mitre.org/data/definitions/1098.html). It reports the destructor of a C++ class that owns memory through a raw pointer, releasing it with `delete`, `delete[]` or `free()`, when no copy constructor for that class is declared anywhere in the scanned files.

## Why This Matters

Without a user-declared copy constructor the compiler generates one that copies the pointer, not what it points to. Pass the object by value, return it, or put it in a `std::vector`, and two objects own the same memory: the first destructor frees it and the second frees it again, or reads it after it was freed.

Not reported: classes with a copy constructor, including a deleted one (`Name(const Name&) = delete`), classes that declare a move constructor or move assignment (which suppresses the implicit copy), classes marked non-copyable (`boost::noncopyable`, `DISALLOW_COPY_AND_ASSIGN`, `Q_DISABLE_COPY`), destructors that release nothing, and comments.

## What Gets Flagged

```cpp
class Buffer {
public:
    explicit Buffer(std::size_t n) : data_(new char[n]), size_(n) {}
    ~Buffer() { delete[] data_; }      // FLAGGED: no Buffer(const Buffer&)
private:
    char* data_;
    std::size_t size_;
};

Session::~Session()                     // FLAGGED
{
    delete user_;
}
```

## Remediation

1. Hold the memory in `std::unique_ptr`, `std::vector` or `std::string` and drop the destructor (rule of zero).
2. Otherwise define the copy constructor and copy assignment to deep-copy, or delete them (`= delete`).
3. For a confirmed false positive, add a `// vulnetix-ignore: VNX-1098` comment on the line.
