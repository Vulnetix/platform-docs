## Overview

This rule flags an allow-list regular expression (a single character class, `\d`, `\w` or `.` with `+`, `*` or `{n,m}`) used to validate a value when it is anchored at only one end, or is bounded by a length quantifier and anchored at neither, so the check passes as soon as part of the value conforms. It covers Python `re.search`/`re.match`, JavaScript `RegExp.test` and `String.match`/`search`, Go `regexp.MatchString`, Java `Matcher.find()`/`lookingAt()`, PHP `preg_match` and Ruby `=~`/`match?`, and in Ruby `^`/`$` (line anchors) used instead of `\A`/`\z`. Patterns are read at the call or from a named constant compiled in the same file. This maps to [CWE-777: Regular Expression without Anchors](https://cwe.mitre.org/data/definitions/777.html).

Not reported: fully anchored patterns, `re.fullmatch`, `String.matches`, negated classes, unanchored patterns without a length bound (a "contains a digit" test is legitimate), match objects used to extract text, comments and strings.

## Why this matters

`^[a-z0-9]+` accepts `abc; rm -rf /`, and a Ruby `/^[a-z0-9]+$/` accepts `abc\n<script>` because `$` matches at the newline. The validation passes and the rest of the value reaches the sink unchecked.

## What gets flagged

```python
if not re.match(r"[a-zA-Z0-9_]+", name):     # FLAGGED: no end anchor
    abort(400)
```

```javascript
if (!/[0-9]{1,10}$/.test(req.params.id)) {   // FLAGGED: no start anchor
```

```ruby
validates_format_of :handle, with: /^[a-z_]+$/i, multiline: true   # FLAGGED: line anchors
```

## Remediation

```python
if not re.fullmatch(r"[a-zA-Z0-9_]+", name):
    abort(400)
```

```javascript
if (!/^[0-9]{1,10}$/.test(req.params.id)) { ... }
```

```ruby
validates_format_of :handle, with: /\A[a-z_]+\z/i
```
