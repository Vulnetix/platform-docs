## Overview

VNX-939 maps to [CWE-939: Improper Authorization in Handler for Custom URL Scheme](https://cwe.mitre.org/data/definitions/939.html). Any installed app or any web page can open a custom-scheme (`myapp://`) or app link, so the URI an Activity receives is chosen by an attacker. A handler that loads it into a WebView, turns it into an Intent, or picks the component to launch from it lets that attacker drive the app.

## What gets flagged

```java
webView.loadUrl(getIntent().getDataString());          // flagged

Uri data = getIntent().getData();
String cls = data.getQueryParameter("screen");
i.setClassName(this, cls);                              // flagged
```

```kotlin
val next = intent?.data?.getQueryParameter("next")
val launch = Intent.parseUri(next, Intent.URI_INTENT_SCHEME)   // flagged
```

Not flagged: a link whose scheme or host is checked first (`getHost()`, `link.host != ...`, `startsWith`, an allowlist or validator call), constant URLs and class names, intent string extras (VNX-ANDROID-002), test code, comments and string literals. Flows across methods or files are not followed, and the manifest's intent-filter is not read.

## Remediation

Check the scheme and host against an allowlist before acting on the link, and map path values to known screens rather than passing them to `setClassName` or `Intent.parseUri`:

```java
Uri uri = getIntent().getData();
if (uri == null || !"https".equals(uri.getScheme()) || !ALLOWED_HOSTS.contains(uri.getHost())) {
    finish();
    return;
}
webView.loadUrl(uri.toString());
```
