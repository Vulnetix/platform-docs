## Overview

VNX-215 maps to [CWE-215: Insertion of Sensitive Information Into Debugging Code](https://cwe.mitre.org/data/definitions/215.html). Debugging facilities exist to show internal state: stack frames with their local variables, source code, request headers and bodies, SQL statements, settings and process memory. Enabled in production, they hand all of it to whoever triggers an error or reaches the debug port.

| Platform | Reported |
|---|---|
| Python | `cgitb.enable()` (also through `import cgitb as x`) unless `display=0`; Django Debug Toolbar `SHOW_TOOLBAR_CALLBACK` set to `lambda request: True` |
| Node.js | `app.use(errorhandler())` with the `errorhandler` package, outside a `NODE_ENV` / `app.get('env')` / development check; `--inspect=0.0.0.0` / `--inspect-brk=0.0.0.0` in a Dockerfile, package.json, compose file or shell script; `inspector.open(port, '0.0.0.0')` |
| ASP.NET Core | `UseDeveloperExceptionPage()` and `UseDatabaseErrorPage()` outside `IsDevelopment()`, `IsEnvironment()` or `#if DEBUG` |

A guard counts on the same line or on a condition line up to eight lines above at a shallower indent.

## What gets flagged

```javascript
app.use(errorhandler());   // FLAGGED
```

```dockerfile
CMD ["node", "--inspect=0.0.0.0:9229", "server.js"]   # FLAGGED
```

```python
cgitb.enable()   # FLAGGED
```

```csharp
app.UseDeveloperExceptionPage();   // FLAGGED (no IsDevelopment() check)
```

## What is not flagged

- The same calls inside `if (process.env.NODE_ENV === 'development')`, `if (app.Environment.IsDevelopment())`, `if (!app.Environment.IsProduction())` or, for `cgitb`, `if os.environ.get("APP_DEBUG"):`.
- `cgitb.enable(display=0, logdir=...)`, a toolbar callback that checks `DEBUG` or `INTERNAL_IPS`, `--inspect` with no host or bound to `127.0.0.1`.
- A project's own error-handling middleware, comments, strings and test code.
- Django `DEBUG = True` (VNX-PY-006), the Flask/Werkzeug debugger (VNX-PY-008) and Go pprof endpoints (VNX-GO-019), which have their own rules.

## Remediation

```javascript
if (process.env.NODE_ENV === 'development') {
  app.use(errorhandler());
}
```

## Suppressing this rule

Put a `nosec` comment on the line, or on line 1 to cover the whole file. Use the comment marker of the file's language (`#`, `//`, `--` or `;`):

```text
# nosec vnx-215
// nosec vnx-215
```

Or record an ignore rule: `vulnetix ignore add --rule vnx-215 --reason "..."`. See [Suppressing findings](/sast/guides/suppressing-findings/).
