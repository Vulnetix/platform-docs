## Overview

VNX-237 maps to [CWE-237: Improper Handling of Structural Elements](https://cwe.mitre.org/data/definitions/237.html). It reports a parser of untrusted form or query data whose limit on structural elements has been removed:

- **Node.js / TypeScript:** an option of `express.urlencoded()`, `bodyParser.urlencoded()`, `qs.parse()` or `querystring.parse()` set to `Infinity` (or `Number.MAX_SAFE_INTEGER`, `MAX_VALUE`, `POSITIVE_INFINITY`) or far past the library default: `parameterLimit` of 100000 or more, `arrayLimit` of 10000 or more, `depth` of 50 or more, and querystring's `maxKeys: 0`, which means unlimited.
- **Python:** Django's `DATA_UPLOAD_MAX_NUMBER_FIELDS` or `DATA_UPLOAD_MAX_NUMBER_FILES`, Werkzeug's `max_form_parts` or Flask's `MAX_FORM_PARTS` set to `None`; and `urllib.parse.parse_qs()`/`parse_qsl()` of a raw request body (`self.rfile.read()`, `request.body`, `request.get_data()`, `environ['wsgi.input'].read()`) without `max_num_fields`.

## Why This Matters

The limits exist because parsing cost grows with the number and nesting of elements, not only with body size. Without them a single small request such as `a[][][]...=1` or a million `&x=1` pairs makes the server allocate a huge object and spend seconds of CPU on it.

Not reported: limits at or near the defaults, a `depth` option of an unrelated API (`util.inspect`, a tree walker), `parse_qs` of a URL's query string, comments, string values and test code.

## What Gets Flagged

```javascript
app.use(express.urlencoded({ extended: true, parameterLimit: 10000000 }));
app.set("query parser", (str) => qs.parse(str, { depth: Infinity }));
```

```python
DATA_UPLOAD_MAX_NUMBER_FIELDS = None

body = environ["wsgi.input"].read(size).decode()
form = parse_qs(body)
```

## Remediation

Keep the defaults, or set a bound sized to the largest legitimate form:

```javascript
app.use(express.urlencoded({ extended: true, parameterLimit: 2000 }));
```

```python
form = parse_qs(body, max_num_fields=200)
```
