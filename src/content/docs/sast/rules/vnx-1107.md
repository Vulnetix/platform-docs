## Overview

VNX-1107 maps to [CWE-1107: Insufficient Isolation of Symbolic Constant Definitions](https://cwe.mitre.org/data/definitions/1107.html). The same symbolic constant, with the same name and the same literal value, is defined separately in two or more Java source files (static final fields, or interface fields) instead of once in a shared constants class that the others reference. Each copy is changed on its own, so a timeout, retry limit, URL or key length that is meant to be one value drifts between classes. Reported: every duplicate definition, on the line that names the constant. Not reported: constants defined once and imported elsewhere, same names with different values (TAG, per-class limits), loggers and other non-literal initialisers, serialVersionUID, trivial values (true/false, 0, 1, -1, empty string, null), definitions repeated inside one file, generated sources (Android BuildConfig, protoc output and other files with a generator header before the first type declaration, or @Generated; an IDE's 'Auto-generated method stub' comment does not count), and test files. Only literal values are compared; constants computed from expressions are not.

## Why this matters

Two classes that each declare `MAX_RETRIES = 5` hold two constants that only happen to agree today. A change to one leaves the other behind, and the code that was meant to share one value no longer does.

## What gets flagged

```java
// OrderService.java
private static final int MAX_RETRIES = 5;   // FLAGGED
// InvoiceService.java
static final int MAX_RETRIES = 5;           // FLAGGED
```

Not flagged: a constant defined once in a shared class and imported, the same name with different values (`TAG = "OrderService"`), loggers, `serialVersionUID`, trivial values (`0`, `1`, `""`, `false`) and test files.

## Remediation

Move the constant to one shared constants class (or configuration) and reference it from every class that needs it.
