## Overview

VNX-1126 maps to [CWE-1126: Declaration of Variable with Unnecessarily Wide Scope](https://cwe.mitre.org/data/definitions/1126.html). Reports a Python global statement inside a function or method body (global counter, global a, b), which makes the function rebind a module-level variable: every caller, thread and request then shares and mutates that one binding, so state set for one caller leaks into the next. The finding is the global line itself. Not reported: a global statement at module level (it has no effect), nonlocal (closure scope), globals that are only module dunders such as __doc__ or __all__, the word 'global' in a comment, a string or prose, and test files (including conftest.py). A global line inside a triple-quoted string is not a statement and is not reported. Whether a particular module-level variable should be wider than its function is a design judgement; the rule reports the statement that widens it.

## What gets flagged

```python
counter = 0

def record(user):
    global counter          # FLAGGED: function rebinds module state
    counter += 1

global settings             # not flagged: module level, no effect
```

1. Review each flagged line and determine whether the pattern represents a real instance of CWE-1126 or a false positive.
2. Replace the flagged construct with a documented safe alternative appropriate to your language and framework.
3. For confirmed false positives, add a `# vulnetix-ignore: VNX-1126` comment on the line.
4. Ensure equivalent test coverage exists to prevent regression.
