## Overview

VNX-1118 maps to [CWE-1118: Insufficient Documentation of Error Handling Techniques](https://cwe.mitre.org/data/definitions/1118.html). It reports a Python function that:

- has a docstring documenting its interface in sections: Google style (`Args:`, `Returns:`), NumPy style (`Parameters` / `Returns` underlined), or Sphinx fields (`:param x:`, `:returns:`, `:rtype:`); and
- raises a named exception itself (`raise ValueError(...)`, `raise errors.AuthError(...) from exc`) that the docstring never mentions, with no `Raises` section or `:raises:` field.

It is reported once per function, on the first such `raise`. A bare `raise`, `raise NotImplementedError` and a raise inside a nested function are not reported, nor are functions with no docstring or only a one-line summary: there the project does not document a contract, so a missing Raises section is not an omission from one.

## Why this matters

When a documented contract lists every argument but none of the errors, callers handle only the errors they discover by reading the body or by failing in production. Unhandled exceptions surface as 500 pages with stack traces, abort transactions halfway through, or are caught by an over-broad `except` that hides a security failure.

## What gets flagged

```python
def charge(card, amount):
    """Charge a card.

    Args:
        card: The stored card token.
        amount: Amount in cents.
    """
    if amount <= 0:
        raise ValueError("amount must be positive")   # FLAGGED
```

```python
def charge(card, amount):
    """Charge a card.

    Args:
        card: The stored card token.

    Raises:
        ValueError: if amount is not positive.
    """
    raise ValueError("amount must be positive")       # NOT FLAGGED
```

## Remediation

1. Add a `Raises:` section (Google), a `Raises` block (NumPy) or `:raises ExcType:` fields (Sphinx) naming every exception the function raises on purpose and when.
2. Document exceptions that callers are expected to handle; re-raises of unexpected errors do not need listing.
