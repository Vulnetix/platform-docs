## Overview

VNX-447 maps to [CWE-447: Unimplemented or Unsupported Feature in UI](https://cwe.mitre.org/data/definitions/447.html). A user who switches on two-factor authentication, changes a password or enables encryption is told it worked. If the method behind the button is a stub, nothing changed and the user believes they are protected.

The rule reports:

1. **Silent security stubs.** A method whose name is a set/enable/disable/change/reset/revoke/verify/validate/enforce verb naming a password, MFA/2FA/OTP, encryption, SSL/TLS, audit, lockout, CAPTCHA, CSRF, session, permission, role, token, credential, signature or certificate, whose body is empty, only comments, `return;` or `return true;`.
2. **Endpoints for features that do not exist.** A Spring `@*Mapping`, JAX-RS `@GET/@POST/...` or servlet `doGet/doPost/...` whose whole body throws `UnsupportedOperationException` or `NotImplementedException`.

Not reported: `UnsupportedOperationException` in ordinary methods (read-only collections and iterators fail loudly, which is correct), a throw inside one branch of an implemented handler, empty non-security methods, dependency setters such as `setSessionFactory` or `setPasswordEncoder`, comments, strings and test files.

## What gets flagged

```java
// FLAGGED: reports success, changes nothing
public boolean changePassword(String oldPassword, String newPassword) {
    return true;
}

// FLAGGED: an exposed endpoint for a missing feature
@PostMapping("/account/mfa")
public ResponseEntity<Void> enableMfa(@RequestBody MfaRequest req) {
    throw new UnsupportedOperationException("not yet");
}
```

## Remediation

1. Implement the operation, or remove it and the UI that offers it.
2. Until it exists, fail visibly (an error the user sees), never report success.
