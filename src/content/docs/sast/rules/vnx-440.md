## Overview

VNX-440 maps to [CWE-440: Expected Behavior Violation](https://cwe.mitre.org/data/definitions/440.html). `assert` does not behave the way a guard is expected to: `python -O` and `PYTHONOPTIMIZE` remove every assert statement, so a permission check written as an assert vanishes in an optimised deployment, and an `assert False` meant to stop an impossible branch lets execution carry on.

## What gets flagged

Outside test files:

- an assert whose condition (not its message) mentions an authentication, authorisation or integrity decision: `is_authenticated`, `is_admin`, `is_superuser`, `is_staff`, `is_active`, `has_perm`, `has_permission`, `has_role`, `is_owner`, `can_*`, `check_password`, `verify*`, `is_valid*`, `compare_digest`, or a name containing authorized, allowed, permission, csrf, signature or password, or a qualified token name (`api_token`, `auth_token`, `session_token`...). A parenthesised condition on the following lines (`assert (` ... `)`) is read up to its closing parenthesis;
- `assert False`, `assert 0` or `assert None`.

```python
assert request.user.is_staff or request.user.has_perm("billing.delete_invoice")   # FLAGGED
assert hmac.compare_digest(sent, expected), "bad signature"                         # FLAGGED
else:
    assert False, "unknown status"                                                 # FLAGGED

if not request.user.is_staff:
    raise PermissionDenied                                                          # not flagged
```

Not reported: asserts in tests (`tests/`, `test_*.py`, `*_test.py`, `conftest.py`), `assert isinstance(...)` on its own, `inspect.signature()` checks, parser asserts on a bare `token`, other invariants, the words appearing only in the message or a comment, `raise AssertionError(...)`. An assert on request data is VNX-617.

## Remediation

1. Replace security asserts with an explicit `if` and an exception (`PermissionDenied`, `abort(403)`).
2. Replace `assert False` with `raise RuntimeError(...)` or `raise AssertionError(...)`.
