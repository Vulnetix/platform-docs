## Overview

VNX-1053 maps to [CWE-1053: Missing Documentation for Design](https://cwe.mitre.org/data/definitions/1053.html). The weakness has no code shape of its own, so the rule reports the one concrete signal source code carries: a Java or Python comment in which the author says the design or architecture is not documented.

- a `TODO`, `FIXME`, `XXX` or `TBD` marker naming the design or architecture together with documenting, explaining or describing it;
- a statement that design documentation is missing or pending (`no design doc yet`, `undocumented design`, `design doc: TBD`).

## Why This Matters

Code whose design is not written down is hard to review for security: nobody can check the implementation against assumptions and trust boundaries that exist only in someone's head. A comment admitting this is a reliable marker that the review will be done blind.

Not reported: a TODO about documenting a parameter or function, a TODO to design something (the work, not its documentation), the same words in a string literal, files in other languages, and classes or modules without doc comments (a missing docstring is not evidence that the design is undocumented).

## What Gets Flagged

```java
// TODO: document the design of the eviction tiers before anyone else touches this
```

```python
# No design doc yet; the settlement ordering is only in Slack.
```

Not flagged:

```python
# TODO: document the timeout parameter
# TODO: design a better retry strategy
```

## Remediation

1. Write the design down where reviewers will find it: an architecture decision record, a design document linked from the code, or a module-level doc comment.
2. Record the assumptions, trust boundaries and failure behaviour, then remove the marker.

## Suppressing this rule

Put a `nosec` comment on the line, or on line 1 to cover the whole file. Use the comment marker of the file's language (`#`, `//`, `--` or `;`):

```text
# nosec vnx-1053
// nosec vnx-1053
```

Or record an ignore rule: `vulnetix ignore add --rule vnx-1053 --reason "..."`. See [Suppressing findings](/sast/guides/suppressing-findings/).
