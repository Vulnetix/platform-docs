## Overview

VNX-448 maps to [CWE-448: Obsolete Feature in UI](https://cwe.mitre.org/data/definitions/448.html). A deprecated endpoint usually keeps the weaker behaviour it was retired for (an old login flow, an unescaped export) and stops receiving fixes, while clients and attackers can still call it.

The rule reports `@Deprecated`, `@Operation(deprecated = true)` or `@ApiOperation(... deprecated = true)` in the same contiguous annotation block as a URL mapping (`@GetMapping`, `@RequestMapping`, `@GET`, `@Path`...) or a controller class annotation.

Not reported: `@Deprecated` on methods, fields and classes that are not mapped to a URL, an endpoint whose body answers 410 Gone or redirects to its replacement, declarative HTTP clients (`@FeignClient`, Micronaut `@Client`, `@RegisterRestClient`, `@HttpExchange`), Javadoc `@deprecated` tags, comments, strings and test files.

## What gets flagged

```java
// FLAGGED: retired but still routed
@Deprecated
@PostMapping("/v1/login")
public Session legacyLogin(@RequestParam String user, @RequestParam String password) { ... }
```

```java
// NOT FLAGGED: the old route only says it is gone
@Deprecated
@GetMapping("/v1/export")
public ResponseEntity<Void> legacyExport() {
    return ResponseEntity.status(HttpStatus.GONE).build();
}
```

## Remediation

1. Remove the mapping once clients have migrated.
2. Until then, answer 410 Gone or redirect to the replacement, and keep it covered by the same security fixes as the current version.
