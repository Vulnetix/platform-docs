## Overview

VNX-483 maps to [CWE-483: Incorrect Block Delimitation](https://cwe.mitre.org/data/definitions/483.html). Without braces only one statement belongs to an `if`, `else`, `for` or `while`. When a second statement is indented as if it belonged too, readers and reviewers see a guarded block where the compiler sees an unconditional statement. That is the shape of Apple's 2014 "goto fail" TLS bug, where a duplicated `goto fail;` skipped signature verification. The rule reports:

1. **Misleading indentation:** a braceless `if`/`else if`/`else`/`for`/`while` header whose single guarded statement is immediately followed by another statement at exactly the same indentation. The finding is on the line that looks guarded but always runs.
2. **Empty `if` body:** `if (condition);` where the semicolon ends the `if`, so the block below runs unconditionally.

Not reported: braced bodies, a braceless body followed by a dedented line, a blank line or a closing brace, `else`/`case`/`default` labels, preprocessor and macro-continuation lines, conditions that span several lines, deliberate empty loops (`while (*p++);`, `for (...);`), the `do { } while (x);` terminator, and comments. A braceless `if` on its own is a style choice and is not reported.

## What gets flagged

```c
if ((err = hash_update(ctx, sig->server)) != 0)
    goto fail;
    goto fail;                   /* FLAGGED: always runs */

if (strcmp(pw, expected) != 0);  /* FLAGGED: empty body */
{
    return -1;
}
```

```java
else
    audit.deny(user);
    user.lock();                 // FLAGGED: always runs
```

## What is not flagged

```c
if (a < 0)
    b[0] = -1;
b[1] = 0;
```

## Remediation

1. Always brace the bodies of `if`, `else`, `for` and `while`.
2. Remove the stray semicolon after an `if` condition.
3. Compile C/C++ with `-Wmisleading-indentation` and `-Wempty-body` (both in `-Wall`/`-Wextra`), and enforce braces with a formatter or linter.

## Suppressing this rule

Put a `nosec` comment on the line, or on line 1 to cover the whole file. Use the comment marker of the file's language (`#`, `//`, `--` or `;`):

```text
# nosec vnx-483
// nosec vnx-483
```
