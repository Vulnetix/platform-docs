## Overview

VNX-605 maps to [CWE-605: Multiple Binds to the Same Port](https://cwe.mitre.org/data/definitions/605.html). It reports socket options that let another socket bind the port a service listens on:

- `setsockopt(..., SO_REUSEPORT, ...)` in C and C++, including a call split over several lines.
- `unix.SetsockoptInt` / `syscall.SetsockoptInt(fd, ..., SO_REUSEPORT, <non-zero>)` in Go, also with the arguments on the following lines.
- `sock.setsockopt(..., socket.SO_REUSEPORT, <non-zero>)` and `reuse_port=True` (asyncio `create_server`) in Python.
- `setsockopt(..., SO_REUSEADDR, ...)` in a Winsock file (`winsock2.h`, `ws2tcpip.h`, `windows.h`) that never sets `SO_EXCLUSIVEADDRUSE`.

Not reported: `SO_REUSEADDR` on POSIX (it only allows reuse of an address in TIME_WAIT), Winsock files that also set `SO_EXCLUSIVEADDRUSE`, `SO_REUSEPORT` set to 0 or False, `getsockopt` reads of the option, `#ifdef SO_REUSEPORT`, and the option name in strings or comments.

## Why this matters

With `SO_REUSEPORT` (Linux, BSD) any socket of the same user can bind the same address and port, and the kernel then spreads new connections across all of them, so a second process can take over part of the service's traffic. On Windows `SO_REUSEADDR` is worse: it lets any process bind over an active listener and steal or spoof its connections.

## What gets flagged

```c
setsockopt(fd, SOL_SOCKET, SO_REUSEPORT, &one, sizeof(one));
```

```go
serr = unix.SetsockoptInt(int(fd), unix.SOL_SOCKET, unix.SO_REUSEPORT, 1)
```

```c
#include <winsock2.h>
setsockopt(s, SOL_SOCKET, SO_REUSEADDR, (const char *)&reuse, sizeof(reuse));
```

```python
sock.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEPORT, 1)
server = await loop.create_server(handler, port=port, reuse_port=True)
```

## Remediation

1. Drop `SO_REUSEPORT` unless the service deliberately load-balances across its own sockets, and then run them under a dedicated user.
2. On Windows, set `SO_EXCLUSIVEADDRUSE` on listening sockets instead of `SO_REUSEADDR`.
3. For a confirmed false positive, add a `// vulnetix-ignore: VNX-605` comment on the line.
