## Overview

VNX-397 maps to [CWE-397: Declaration of Throws for Generic Exception](https://cwe.mitre.org/data/definitions/397.html). It reports a Java method or interface method that declares `throws Exception` or `throws Throwable`, alone, `java.lang.`-qualified or inside a list such as `throws IOException, Exception`, on the signature line or on the `throws` line of a multi-line signature.

Not reported: specific exception types (including names that only start with `Exception`, such as `ExceptionInInitializerError`); a method annotated `@Override`, whose signature the supertype dictates; `main(String[])`, `Callable.call()`, `AutoCloseable.close()` and `InitializingBean.afterPropertiesSet()`; Spring Security configuration methods taking `HttpSecurity`, `WebSecurity`, `AuthenticationManagerBuilder` or `AuthenticationConfiguration`, whose builders throw `Exception` themselves; sample, example and demo directories; a file declaring a `@FunctionalInterface` (a throwing functional interface, like `Callable`, has to declare the generic type); test files, comments, Javadoc and strings.

## Why This Matters

`throws Exception` erases the contract. Every caller has to catch `Exception`, which also catches the runtime exceptions of its own bugs, and the compiler can no longer say when a new failure mode is introduced.

## What Gets Flagged

```java
public Report build(long id) throws Exception {          // FLAGGED

void importAll(String source) throws IOException, Exception;   // FLAGGED

public void replicate(
        Source source,
        Target target)
        throws Exception {                                // FLAGGED
```

## Remediation

1. Declare the checked exceptions the method really throws (`throws IOException, SQLException`).
2. Wrap lower-level failures in a domain exception (`throws ReportException`).
