## Overview

VNX-294 maps to [CWE-294: Authentication Bypass by Capture-replay](https://cwe.mitre.org/data/definitions/294.html). A token that is never too old is a token that can be replayed: once it appears in a log, a proxy, browser history or a forwarded e-mail, whoever holds it is authenticated.

The rule reports:

- **Expiry verification switched off:** jsonwebtoken `{ ignoreExpiration: true }`; PyJWT/python-jose `options={"verify_exp": False}` (inline or in an options dict) and the old `verify_expiration=False`.
- **A leeway of a day or more:** jsonwebtoken/jose `clockTolerance`, PyJWT `leeway=`, jjwt `setAllowedClockSkewSeconds`/`clockSkewSeconds`, Auth0 java-jwt `acceptLeeway`/`acceptExpiresAt` with a literal of 86400 or more, `Long.MAX_VALUE` or `Integer.MAX_VALUE`.
- **A timestamped signature read without a maximum age:** itsdangerous `URLSafeTimedSerializer`/`TimedSerializer`/`TimestampSigner` `.loads()`/`.unsign()` and Django `signing.loads()`/`TimestampSigner().unsign()` without `max_age`.

## What Gets Flagged

```js
return jwt.verify(token, process.env.JWT_KEY, { ignoreExpiration: true });   // FLAGGED
```

```python
serializer = URLSafeTimedSerializer(app.config["SECRET_KEY"])
email = serializer.loads(token, salt="password-reset")    # FLAGGED: never expires
```

```java
.setAllowedClockSkewSeconds(Long.MAX_VALUE)               // FLAGGED
```

## What Is Not Flagged

- `verify_exp: True`, `ignoreExpiration: false`, and a leeway under a day.
- `loads(..., max_age=3600)` and `signing.loads(..., max_age=...)`.
- Untimed serializers and signers, `json.loads`/`pickle.loads`, comments and string literals.

Tokens issued without an `exp` claim are reported by VNX-JWT-002. Nonce or `jti` replay caches are not judged.

## Remediation

Keep expiry verification on and tokens short-lived, refresh them instead of accepting expired ones, and pass `max_age` to every timestamped `loads()`/`unsign()`:

```python
email = serializer.loads(token, salt="password-reset", max_age=3600)
```
