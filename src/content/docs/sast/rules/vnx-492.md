## Overview

VNX-492 maps to [CWE-492: Use of Inner Class Containing Sensitive Data](https://cwe.mitre.org/data/definitions/492.html). It reports inner and anonymous classes that use a private sensitive field of the class that contains them.

## Why this matters

The JVM has no notion of an inner class. Before Java 11, javac gave an inner class access to its outer class's private fields by generating package-visible accessor methods, which any class in the same package can call. The inner object also holds a hidden reference to the outer one, so passing it to other code (a callback, an interceptor) keeps the secret reachable.

## What gets flagged

```java
public class Vault {
    private char[] masterPassword;

    class Unlocker {                          // FLAGGED
        boolean unlock(char[] attempt) {
            return Arrays.equals(attempt, masterPassword);
        }
    }
}
```

```java
private String sessionToken;

Runnable refresher() {
    return new Runnable() {                   // FLAGGED
        public void run() { sessionToken = renew(sessionToken); }
    };
}
```

Not flagged: a `static class` nested class, and inner classes that only touch non-sensitive fields.

## Remediation

1. Make the nested class `static` and pass it only the data it needs.
2. Keep the operation on the secret in the outer class and give the inner class a method to call instead of the field.
3. Compile for Java 11 or later, where nestmate access removes the synthetic accessors.
