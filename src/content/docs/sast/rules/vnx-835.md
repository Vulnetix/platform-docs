## Overview

VNX-835 maps to [CWE-835: Loop with Unreachable Exit Condition ('Infinite Loop')](https://cwe.mitre.org/data/definitions/835.html). A loop such as `while (i < count)` ends only when something in its body moves `i` or `count`. When the body forgets to, the condition that held on entry holds forever: the thread spins, the request never completes, and an attacker who can reach the loop can exhaust CPU.

The rule reads each `while` loop whose condition is `variable <op> bound` (`<`, `<=`, `>`, `>=`, `!=`) and reports it when the body:

- never assigns, increments or rebinds the variable (`i++`, `++i`, `i += 1`, `i = next(i)`, tuple assignment, walrus, `for i in ...`),
- never changes the bound (a plain variable assigned, or the collection behind `len(q)`, `q.size()`, `items.length` mutated through a method call), and
- has no `break`, `return`, `throw`, `raise`, `yield` or exit call.

## What gets flagged

```java
int i = 0;
while (i < count) {          // FLAGGED: i never advances
    total += values[i];
}
```

```python
while pos < end:             # FLAGGED: pos never advances
    ch = text[pos]
    handle(ch)
```

## What is not flagged

- Deliberate infinite loops (`while True:`, `while (true)`, `for (;;)`), which are almost always server or worker loops.
- `do { ... } while (i < n);` loops.
- Loops that advance the variable in any form, or that leave by `break`, `return` or `throw`.
- Conditions on fields or method calls alone, bodies longer than 60 lines, and the pattern in comments or string literals.

## Remediation

Advance the loop variable on every path through the body (or use a `for` loop that does it in the header), and give any loop that waits on external state a timeout or a maximum iteration count.
