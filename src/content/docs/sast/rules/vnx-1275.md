## Overview

VNX-1275 maps to [CWE-1275: Sensitive Cookie with Improper SameSite Attribute](https://cwe.mitre.org/data/definitions/1275.html).

## Why this matters

With `SameSite=None`, or with the attribute switched off, the browser attaches the cookie to requests that other sites start. A session cookie sent this way lets a malicious page make authenticated requests on the user's behalf (cross-site request forgery).

## What gets flagged

```javascript
res.cookie('session', token, { httpOnly: true, secure: true, sameSite: 'none' });
app.use(session({ cookie: { sameSite: false } }));
res.setHeader('Set-Cookie', 'sid=' + sid + '; HttpOnly; SameSite=None');
```

```python
SESSION_COOKIE_SAMESITE = None
resp.set_cookie("userid", user.id, samesite=None, secure=True)
```

Not flagged: `'lax'`, `'strict'`, `true`, a value read from configuration at run time, test files.

## Remediation

1. Use `SameSite=Lax` (or `Strict`) for session and credential cookies.
2. Keep `SameSite=None; Secure` for cookies that must work in a cross-site embed and that carry no credential.
