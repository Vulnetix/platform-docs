## Overview

VNX-205 maps to [CWE-205: Observable Behavioral Discrepancy](https://cwe.mitre.org/data/definitions/205.html). A password hash such as bcrypt or argon2 is deliberately slow. A login that only runs it when the account exists answers an unknown username in a millisecond and a known one with a wrong password in a hundred, even when both return the same message. Timing the responses enumerates accounts.

## What gets flagged

A check that the looked-up account is missing whose branch returns, raises, aborts or throws without hashing, followed within 12 lines by a password verification of that account (`bcrypt.checkpw`, `check_password`, `check_password_hash`, `verify_password`, `pwd_context.verify`, `argon2`/hasher `.verify`, `bcrypt.compare`); and the short-circuit form where the hash is skipped for a missing account.

```python
user = User.query.filter_by(email=request.form["email"]).first()
if user is None:                                                    # flagged
    abort(401)
if not bcrypt.checkpw(request.form["password"].encode(), user.password_hash):
    abort(401)
```

```javascript
if (!account || !(await bcrypt.compare(req.body.password, account.hash))) {  // flagged
  return res.sendStatus(401);
}
```

Not flagged: a branch that verifies against a dummy hash or calls `set_password`/`hashpw` first (as Django's `ModelBackend` does), a verification that runs before the account check, a missing-record check with no password verification after it, comments and strings.

## Remediation

Run the hash on every path:

```python
DUMMY_HASH = bcrypt.hashpw(b"unused", bcrypt.gensalt())

hashed = user.password_hash if user else DUMMY_HASH
ok = bcrypt.checkpw(password.encode(), hashed)
if user is None or not ok:
    abort(401)
```
