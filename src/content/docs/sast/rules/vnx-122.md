## Overview

VNX-122 maps to [CWE-122: Heap-based Buffer Overflow](https://cwe.mitre.org/data/definitions/122.html). It reports two concrete shapes:

1. A string buffer allocated with `malloc`/`xmalloc` or `new char[]` sized by `strlen()` alone (or a sum of `strlen()` calls, or a variable assigned from `strlen()` just above) with no `+ 1`, which a `strcpy`, `strcat`, `sprintf` or `stpcpy` into it then overruns by one byte. The allocation line is reported.
2. A heap buffer allocated with a fixed size (a number, an upper-case constant or a `sizeof`) that then receives an unbounded copy: `strcpy`/`strcat` from a non-literal source, `gets()`, or `sprintf` with an unbounded `%s`. The copy line is reported.

## What Gets Flagged

```c
char *out = malloc(strlen(name));        // FLAGGED: no room for the NUL
strcpy(out, name);

char *buf = (char *)malloc(64);
strcpy(buf, argv[1]);                    // FLAGGED: unbounded copy into 64 bytes

char *p = new char[256];
sprintf(p, "%s/%s", dir, file);          // FLAGGED
```

## What Is Not Flagged

- `malloc(strlen(s) + 1)`, `strdup()`, `snprintf()`, `strncpy()` and `%.40s` precision.
- Byte buffers filled with `memcpy` (no terminator is needed).
- `strcpy` of a string literal, and copies preceded by a `strlen()`/`strnlen()` check between the allocation and the copy.
- Stack buffers, computed sizes and flows across functions (out of scope).

## Remediation

Allocate `strlen(s) + 1` bytes for a copy of `s`, and use bounded copies (`snprintf`, `strlcpy`) sized by the allocation, or size the allocation from the input.
