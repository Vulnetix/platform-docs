## Overview

VNX-495 maps to [CWE-495: Private Data Structure Returned From A Public Method](https://cwe.mitre.org/data/definitions/495.html). It reports public methods that hand out a private array field instead of a copy. VNX-375, the general mutable-return rule, leaves these lines to this rule and reports collections, dates and the other mutable fields.

## Why this matters

Arrays are mutable and returned by reference. A getter that returns `roles` lets the caller write `getRoles()[0] = "admin"` and change the object's own state, bypassing every check the class performs on its setters. Marking the field `final` does not prevent this.

## What gets flagged

```java
public class KeyHolder {
    private byte[] secretKey;
    private final String[] roles;

    public byte[] getSecretKey() {
        return secretKey;                        // FLAGGED
    }

    public String[] getRoles() { return roles; } // FLAGGED
}
```

Not flagged: `return secretKey.clone();`, `return Arrays.copyOf(roles, roles.length);`, returning a `private static final String[] EMPTY = new String[0];`, and non-public methods.

## Remediation

1. Return a copy: `return secretKey.clone();` or `Arrays.copyOf(...)`.
2. Return an unmodifiable view such as `List.of(roles)` or `Collections.unmodifiableList(...)`.
3. For secrets, avoid returning them at all; expose the operation (sign, verify) instead.
