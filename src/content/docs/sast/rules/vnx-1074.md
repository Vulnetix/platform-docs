## Overview

VNX-1074 maps to [CWE-1074: Class with Excessively Deep Inheritance](https://cwe.mitre.org/data/definitions/1074.html). It resolves every `class X extends Y` in the project's Java files by simple class name (headers may carry annotations and put `extends` on the next line) and reports a class with seven or more extends edges above it: every class on the way declared in the project, the last parent possibly a library class. `java.lang.Object` is not counted.

It does not report chains of six edges or fewer (ancestors above a library class cannot be seen), interfaces and `implements` clauses, generic bounds (`class Box<T extends Number>`), chains that loop back on a name (two classes with the same simple name in different packages), test sources, or class text in comments (line or block) and strings.

## Why this matters

Each level adds behaviour a reader must keep in mind and an override that can change what the base classes rely on. Security checks placed in a base class are the ones a deep subclass most easily bypasses by accident.

## What gets flagged

```java
public class Container extends Component { }
public class Panel extends Container { }
// ... ScrollPanel, TabPanel, FormPanel, WizardPanel ...
public final class CheckoutWizard extends WizardPanel { }   // FLAGGED: 7 levels
```

## Remediation

1. Prefer composition: hold a collaborator instead of extending it.
2. Collapse intermediate classes that add little.

## Suppressing this rule

Put a `nosec` comment on the line, or on line 1 to cover the whole file. Use the comment marker of the file's language (`#`, `//`, `--` or `;`):

```text
# nosec vnx-1074
// nosec vnx-1074
```

Or record an ignore rule: `vulnetix ignore add --rule vnx-1074 --reason "..."`. See [Suppressing findings](/sast/guides/suppressing-findings/).
