## Overview

VNX-270 maps to [CWE-270: Privilege Context Switching Error](https://cwe.mitre.org/data/definitions/270.html). It reports an exec, `system`, `popen`, `posix_spawn` or `subprocess` call that follows a temporary privilege drop in the same function, with no permanent drop in between.

## Why This Matters

`seteuid(uid)` changes only the effective user ID; the real user ID stays root. That is the right tool for a short unprivileged section inside a root process, but it is not a context switch for a new program. A program started afterwards inherits root as its real user ID, and any process whose real user ID is root may call `setuid(0)` again. A user's hook script, an editor or a plugin started this way can take back full root with one call.

## What Gets Flagged

```c
if (setegid(gid) != 0 || seteuid(uid) != 0)
    return -1;
execl("/bin/sh", "sh", "-c", hook, (char *)NULL);   /* flagged */
```

```cpp
::setresuid(-1, uid, -1);
::execvp(argv[0], argv);                            // flagged
```

```python
os.seteuid(uid)
subprocess.run(cmd, check=True)                     # flagged
```

Not flagged: a permanent drop before the exec (`setuid(uid)`, `setresuid(uid, uid, uid)`, `setreuid(uid, uid)`, `os.setuid(uid)`, or a `drop_privileges()`-style wrapper); root restored with `seteuid(0)` before the exec, where the program runs as root on purpose ([VNX-272](/sast/rules/vnx-272/) judges whether that is necessary); `subprocess.run(..., user=uid)`; the two calls in different functions; and the names in comments or string literals.

## Remediation

1. Fork, then in the child drop permanently before exec: `setgroups`, `setgid(gid)`, `setuid(uid)` (or `setresgid`/`setresuid` with all three IDs), and check each result.
2. In Python, use `subprocess.run(cmd, user=uid, group=gid, extra_groups=[])`, which performs the permanent drop in the child.
