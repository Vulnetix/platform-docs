## Overview

VNX-606 maps to [CWE-606: Unchecked Input for Loop Condition](https://cwe.mitre.org/data/definitions/606.html). It reports a loop `for (...; i < N; ...)`, `while (i < N)` or Go `for i := range N` where `N`, within the 25 lines above, was:

- **C/C++:** assigned from `atoi`/`atol`/`strtol`/`strtoul`/`ntohl`/`ntohs` over `argv`, `getenv` or `optarg`, or read with `scanf("%u", &N)`.
- **Java:** assigned from `Integer.parseInt`/`valueOf`, `Long.parseLong` or `Scanner.nextInt` over `request.getParameter`/`getHeader` (directly or through one variable), or a `@RequestParam`/`@PathVariable`/`@QueryParam` int parameter.
- **Go:** assigned from `strconv.Atoi`/`ParseInt`/`ParseUint` over `r.URL.Query()`, `FormValue`, `Header.Get`, gin `c.Query`/`c.Param`, `mux.Vars` or `os.Args`, directly or through one variable.

Not reported: a bound compared against a limit in an `if` before the loop, a bound clamped with `min()`/`Math.min` or a clamp helper, or passed to a verify/validate function, a loop in a different function from the parse, count-down loops over `ntohs`/`ntohl` values, a loop header with a second condition (`i < n && i < MAX`), constants, collection lengths and loops over collections.

## Why this matters

A caller who chooses the iteration count chooses how much CPU and memory the request costs. One request with `rows=2000000000` keeps a worker busy for minutes.

## What gets flagged

```java
int rows = Integer.parseInt(request.getParameter("rows"));
for (int i = 0; i < rows; i++) {
```

```go
raw := r.URL.Query().Get("times")
times, err := strconv.Atoi(raw)
for i := 0; i < times; i++ {
```

```c
scanf("%u", &num);
for (unsigned int i = 0; i < num; i++) {
```

```c
int times = atoi(argv[1]);
while (times-- > 0) {
```

## Remediation

1. Reject or clamp the value before the loop: `if (rows > MAX_ROWS) return error;` or `rows = Math.min(rows, MAX_ROWS);`.
2. Prefer pagination over caller-chosen batch sizes.
3. For a confirmed false positive, add a `// vulnetix-ignore: VNX-606` comment on the line.

