## Overview

VNX-768 maps to [CWE-768: Incorrect Short Circuit Evaluation](https://cwe.mitre.org/data/definitions/768.html). It reports a Java or C# condition in which a null check is joined to the rest of the expression by `&` or `|` instead of `&&` or `||`, and the right operand dereferences the variable just checked:

- `x != null & x.isPaid()`, `null != x & x[0] ...`
- `x == null | x.isEmpty()`

A guard at the end of a line whose right operand continues on the next line is also read.

Not reported: `&&`, `||`, `&=` and `|=`; bitwise arithmetic on integers; null checks joined by `&` whose right operand does not dereference the guarded variable (no failure, only style); C# null-conditional access (`x?.Items`); comments and string literals.

## Why This Matters

`&` and `|` evaluate both operands. The null check is evaluated, its result is ignored for control flow, and the dereference runs anyway: a null value throws `NullPointerException` / `NullReferenceException`. Where the check guards an authorisation or validation step, the exception path can skip it or crash the request.

## What Gets Flagged

```java
if (order != null & order.isPaid()) { ... }        // flagged
return name == null | name.trim().isEmpty();       // flagged
```

```csharp
return cart != null & cart.Items.Count > 0;        // flagged
```

Not flagged:

```java
if (order != null && order.isPaid()) { ... }
return (a != null) & (b != null);
```

## Remediation

Use the short-circuit operators `&&` and `||` whenever the right operand depends on the left one.
