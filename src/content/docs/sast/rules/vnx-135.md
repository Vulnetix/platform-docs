## Overview

VNX-135 maps to [CWE-135: Incorrect Calculation of Multi-Byte String Length](https://cwe.mitre.org/data/definitions/135.html). It reports:

1. `malloc`/`xmalloc`/`alloca`/`realloc` sized by `wcslen()` with no `sizeof` (and no `* 2`/`* 4`): one byte per wide character, or too few bytes for a `wcstombs()` result.
2. `memcpy`/`memmove`/`memcmp`/`memset` given a `wcslen()` count with no `sizeof`, which copies only part of the string.
3. A function that counts in wide characters (`wcsncpy`, `wcsncat`, `wcslcpy`, `wmemcpy`, `wmemset`, `swprintf`, `mbstowcs`, `fgetws`, `MultiByteToWideChar`, `GetWindowTextW`, ...) given `sizeof(buf)`, a byte count two to four times the buffer's length in characters.
4. `strlen()` on a variable declared `wchar_t`/`WCHAR`, usually through a `(char *)` cast.

## What Gets Flagged

```c
wchar_t *dst = malloc(wcslen(src) + 1);          // FLAGGED: bytes, not wide chars
wchar_t buf[64];
wcsncpy(buf, who, sizeof(buf));                  // FLAGGED: 256 counted as chars
memmove(dst, src, wcslen(src));                  // FLAGGED
return strlen((const char *)title);              // FLAGGED: title is wchar_t *
```

## What Is Not Flagged

- Sizes multiplied by `sizeof(wchar_t)` or `sizeof(*p)`.
- Counts written `sizeof(buf) / sizeof(buf[0])`, `ARRAY_SIZE()` or `_countof()`.
- `new wchar_t[wcslen(s) + 1]` (an element count), and narrow strings.
- UTF-8 length mistakes in other languages (out of scope).

## Remediation

Multiply wide-character counts by `sizeof(wchar_t)` when a byte count is needed, pass element counts (`_countof(buf)`) to wide-character APIs, and use `wcslen()` for wide strings.
