## Overview

VNX-334 maps to [CWE-334: Small Space of Random Values](https://cwe.mitre.org/data/definitions/334.html). It reports a secret drawn as a random integer from a range of fewer than 2^32 values, when the same line names it as a token, secret, key, password, salt, session id, CSRF, API key, reset or invite value.

## Why this matters

However good the generator, a value chosen from a million possibilities is guessed in a million tries, and often far fewer when the attacker can try many tokens at once. Session ids and reset tokens need at least 128 bits.

## What gets flagged

```python
# FLAGGED
session_id = random.randint(1000, 9999)
reset_token = secrets.randbelow(1000000)
```

```java
// FLAGGED: nextInt() is 32 bits at most, even from SecureRandom
int sessionId = rnd.nextInt(100000);
```

```javascript
// FLAGGED
const resetToken = crypto.randomInt(100000, 999999);
const sessionId = Math.floor(Math.random() * 1000000);
```

## What is not flagged

- Bounds from variables or expressions, and ranges of 2^32 and more (`secrets.randbelow(2**128)`).
- Random integers with no security name: indexes, delays, ports, colours, dice.
- One-time passcodes and PINs: a 6-digit OTP is the norm and is protected by expiry and attempt limits.
- Comments and test files.

## Remediation

Generate tokens from at least 128 random bits: `secrets.token_urlsafe(32)`, `crypto.randomBytes(32).toString('hex')`, or 16+ bytes from `SecureRandom.nextBytes`.
