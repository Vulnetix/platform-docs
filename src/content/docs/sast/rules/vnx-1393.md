## Overview

VNX-1393 maps to [CWE-1393: Use of Default Password](https://cwe.mitre.org/data/definitions/1393.html). Vendor and framework defaults are the first credentials an attacker tries, and they appear in public documentation and wordlists. The rule reports a password-named key (ending in `password`, `passwd`, `pwd`, `passphrase` or `_pass`) whose value is exactly one of: `password`, `admin`, `administrator`, `root`, `toor`, `changeme`, `changeit`, `change_me`, `default`, `guest`, `secret`, `postgres`, `mysql`, `oracle`, `manager`, `tomcat`, `raspberry`.

## What Gets Flagged

```python
DB_PASSWORD = "postgres"
psycopg2.connect(host="db", user="app", password="password")
SMTP_PASSWORD = os.environ.get("SMTP_PASSWORD", "secret")   # default when unset
```

```javascript
rabbitPass: process.env.RABBIT_PASSWORD || "guest",
```

```yaml
environment:
  POSTGRES_PASSWORD: postgres
  - REDIS_PASSWORD=root
  DB_PASSWORD: ${DB_PASSWORD:-changeme}
```

```properties
server.ssl.key-store-password=changeit
```

Not flagged: comparisons (`if password == "admin"`), labels and field names (`"Password"`, `PASSWORD_FIELD = "password"`), a literal that starts a concatenation, text inside a longer string or a comment, test, fixture and docs paths, and config templates (`.env.example`, `.sample`, `.dist`). Weak but non-default values such as `123456` are VNX-1391; a default password set for a default account (`<user name="admin" password="admin" />`, a `USERNAME = "admin"` constant above `PASSWORD = "admin"`, `MYSQL_ROOT_PASSWORD=root`, `User Id=sa;Password=password`) is reported by VNX-1392 as a default credential pair, so the line is reported once; hard-coded passwords in general are VNX-SEC-014 and VNX-259.

## Remediation

1. Generate a unique, random secret per deployment and inject it from a secrets manager or the environment.
2. Do not fall back to a default: fail to start when the variable is unset.
3. Force a change of any vendor default at first use (initial admin, keystore, database superuser).

## Suppressing this rule

Put a `nosec` comment on the line, or on line 1 to cover the whole file. Use the comment marker of the file's language (`#`, `//`, `--` or `;`):

```text
# nosec vnx-1393
// nosec vnx-1393
```

Or record an ignore rule: `vulnetix ignore add --rule vnx-1393 --reason "..."`. See [Suppressing findings](/sast/guides/suppressing-findings/).
