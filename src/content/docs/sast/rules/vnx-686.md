## Overview

VNX-686 maps to [CWE-686: Function Call With Incorrect Argument Type](https://cwe.mitre.org/data/definitions/686.html). A variadic call reads each argument as the type its conversion names. Passing a 64-bit `size_t` to `%d`, an integer to `%s` or a `std::string` object to `%s` is undefined behaviour: the call reads the wrong bytes, or dereferences an integer as a pointer.

## What gets flagged

```c
printf("name is %d bytes\n", strlen(name));   // FLAGGED: size_t to %d
printf("status %s\n", 404);                   // FLAGGED: integer to %s
sprintf(buf, "%d items", "ten");              // FLAGGED: string to %d
printf("%f\n", 1);                            // FLAGGED: int to %f
scanf("%d", count);                           // FLAGGED: int count; needs &count

size_t len = strlen(s);
double ratio = 0.5;
printf("len=%d\n", len);                      // FLAGGED: declared size_t
printf("ratio=%d\n", ratio);                  // FLAGGED: declared double
```

```cpp
printf("name=%s id=%d\n", name, id);          // FLAGGED: name is a std::string
std::printf("user %s\n", std::to_string(id)); // FLAGGED
```

## What is not flagged

- `%zu`/`%zd` and `%lu`, explicit casts, and `.c_str()`.
- Pointers and arrays passed to scanf.
- Calls whose argument count differs from the format (VNX-685 reports those), calls split over several lines, and macro-built formats.
- Comments and string literals.

## Remediation

Use the conversion that matches the type (`%zu` for `size_t`), pass `.c_str()` for C++ strings and `&var` to scanf, and compile with `-Wall -Wformat=2`.
