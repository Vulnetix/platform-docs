## Overview

VNX-620 maps to [CWE-620: Unverified Password Change](https://cwe.mitre.org/data/definitions/620.html). If a change-password endpoint does not ask for the current password, anyone holding the session (a stolen cookie, a CSRF request, an XSS payload) can take over the account for good.

The rule looks for a password write (`set_password()`, `setPassword()`, an assignment to `user.password`, an ORM `update`/`$set` of `password`, or `UPDATE ... SET password`) in a handler named or routed as a password change that reads the request, with no current-password check in the 40 lines above. A check guarded by `if (currentPassword && ...)` does not count, because the client can skip it by leaving the current password out.

## What Gets Flagged

```python
@bp.route("/change_password", methods=["POST"])
def change_password():
    new_password = request.form["new_password"]
    current_user.set_password(new_password)      # flagged
```

```typescript
if (currentPassword && hash(currentPassword) !== user.password) {
  return res.status(401).send('Current password is not correct.')
}
await user.update({ password: newPassword })     // flagged: the check is optional
```

```java
user.setPassword(passwordEncoder.encode(form.getNewPassword()));  // flagged
```

```csharp
lblResult.Text = store.UpdateAccountPassword(accountId, txtNew.Text);  // flagged: no current-password check
```

Not flagged: handlers that call `check_password`, `bcrypt.compare`, `PasswordEncoder.matches`, `password_verify` or compare against an old/current password; Django's `PasswordChangeForm`; password-reset, invitation and activation flows; administrator endpoints; registration; test files.

## Remediation

Require the current password and verify it before writing the new one:

```python
if not current_user.check_password(request.form["old_password"]):
    abort(403)
current_user.set_password(request.form["new_password"])
```
