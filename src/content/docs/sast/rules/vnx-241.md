## Overview

VNX-241 maps to [CWE-241: Improper Handling of Unexpected Data Type](https://cwe.mitre.org/data/definitions/241.html). It reports a Python JSON request body value used as a `str` when the client decides its type: a `str` method (`lower`, `upper`, `strip`, `split`, `replace`, `startswith`, `endswith`, `encode`, `casefold` and similar) on a field of `request.json` or `request.get_json()` (Flask), DRF `request.data` or `json.loads(request.body)` (Django), inline, through the dict assigned from the body, or through a variable assigned from one of its fields.

The same weakness in Node.js/TypeScript, a string method or `.length` on a value of `req.query` or `req.body`, is reported by [VNX-1287](/sast/rules/vnx-1287/), and this rule does not report it a second time.

## Why this matters

A JSON body can hold any type. A JSON number, list, object or `null` where a string was expected makes Python's `.lower()` or `.strip()` raise `AttributeError`, which turns a malformed request into a crash or a 500 rather than a 400.

Not reported: a value checked with `isinstance(..., str)` or `type()` in the ten lines above, a value coerced with `str()`, Flask `request.args`/`request.form`/`request.headers` (always strings), comments and string literals.

## What gets flagged

```python
email = request.json["email"].lower()

data = json.loads(request.body)
new_name = data["name"].strip()   # {"name": 5} raises AttributeError
```

## Remediation

```python
email = request.json.get("email")
if not isinstance(email, str):
    abort(400)
```

Validating the whole request with a schema (pydantic, marshmallow, DRF serializers) fixes every field at once.
