## Overview

VNX-400 maps to [CWE-400: Uncontrolled Resource Consumption](https://cwe.mitre.org/data/definitions/400.html). CWE-400 is broad; this rule reports its most concrete line-level form in Python: a Flask, Django or DRF request value (`request.args`, `form`, `values`, `json`, `GET`, `POST`, `data`, `query_params`, `headers`, `cookies`), used directly or through a variable assigned from it in the 10 lines above, as

- the count of `range(...)`,
- the duration of `time.sleep(...)`,
- the size of `bytearray()`, `bytes()`, `os.urandom()`, `secrets.token_bytes()`/`token_hex()`/`token_urlsafe()`, numpy `zeros`/`ones`/`empty`/`full`/`arange`, `.read()` or `.recv()`,
- the width of `str.zfill()`, `ljust()`, `rjust()` or `center()`,
- the multiplier of a string or list repetition (`"=" * n`, `[x] * n`),
- the exponent of `**`,

with no upper bound in between.

Not reported: a value bounded first (`min(...)`, an `if` comparison of the variable, a `max`/`min` clamp reassignment), constants, environment and settings values, `len()` of the input, test files, comments and strings. A limit enforced in another function or by a schema validator is not seen, and unbounded work driven by other sources is out of scope.

## Why This Matters

`?count=1000000000` turns one request into a billion iterations, a gigabyte allocation or a worker asleep for a day. A handful of such requests takes the service down without any authentication.

## What Gets Flagged

```python
n = request.args.get("count", type=int)
return jsonify([make_code() for _ in range(n)])       # FLAGGED

delay = float(request.GET.get("delay", "0"))
time.sleep(delay)                                      # FLAGGED

exp = int(request.form["exp"])
return str(10 ** exp)                                  # FLAGGED
```

Not flagged:

```python
n = min(request.args.get("count", 10, type=int), MAX_COUNT)
return jsonify([make_code() for _ in range(n)])
```

## Remediation

1. Clamp request-supplied sizes to a fixed maximum (`min(value, LIMIT)`) or reject values above it with 400.
2. Enforce request body and upload size limits in the framework (`MAX_CONTENT_LENGTH`, `DATA_UPLOAD_MAX_MEMORY_SIZE`).
