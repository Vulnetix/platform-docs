## Overview

VNX-615 maps to [CWE-615: Inclusion of Sensitive Information in Source Code Comments](https://cwe.mitre.org/data/definitions/615.html). It reports a comment, including a line inside a `/* ... */` block and a trailing comment after code (a whole-line comment is `#` in Python; `//`, `/* */`, `*` or `<!-- -->` elsewhere) where a credential name (password, passwd, passphrase, secret, client_secret, api_key, access/auth/api/refresh token, private key, secret/access key, `*_pass`) is followed by `:` or `=` and a literal of six or more characters containing a digit or a symbol.

Not reported: parameter documentation and prose (`@param password the user's password`, `password: must be 12 characters`), references to the environment, settings or a function call (`os.Getenv(...)`, `process.env.X`, `settings.API_KEY`), placeholders (`changeme`, `xxxxxxxx`, `********`, `<your password>`, `${VAR}`), URLs, credentials in code (hard-coded credential rules cover those) and provider-format tokens (the secrets rules cover those).

## Why this matters

Comments ship with the source, are copied into forks and bundles, and stay in version history after the line is deleted. A password left in a comment is disclosed to everyone who can read the repository.

## What gets flagged

```python
# password = "R3port!ng2023"
```

```java
// String password = "Adm1n@2024";
/* passwd=letmein99 for the staging box */
```

```javascript
 * api_key: 4f9a2c71e8b3d6a0
```

```python
conn = connect(password=os.environ["DB_PASSWORD"])  # old password: Pr0d#Db2023
```

## Remediation

1. Remove the comment and rotate the credential: it is in history already.
2. Keep credentials in a secrets manager or environment variables, and document the variable name instead of its value.
3. For a confirmed false positive, add a `// vulnetix-ignore: VNX-615` comment on the line.

## Suppressing this rule

Put a `nosec` comment on the line, or on line 1 to cover the whole file. Use the comment marker of the file's language (`#`, `//`, `--` or `;`):

```text
# nosec vnx-615
// nosec vnx-615
```

Or record an ignore rule: `vulnetix ignore add --rule vnx-615 --reason "..."`. See [Suppressing findings](/sast/guides/suppressing-findings/).
