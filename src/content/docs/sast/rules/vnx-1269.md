## Overview

VNX-1269 maps to [CWE-1269: Product Released in Non-Release Configuration](https://cwe.mitre.org/data/definitions/1269.html).

## Why this matters

A debugger hook left in shipped code stops the process at an interactive prompt. That hangs the worker, or hands a Python shell to whoever owns the terminal. A remote-debug listener (`debugpy.listen`, `ptvsd.enable_attach`) is worse: anyone who can reach the port can run arbitrary code.

## What gets flagged

```python
pdb.set_trace()
import ipdb; ipdb.set_trace()
breakpoint()
debugpy.listen(("0.0.0.0", 5678))
ptvsd.enable_attach(address=("0.0.0.0", 3000))
```

Not flagged: a hook inside `if args.pdb:` or `if os.environ.get("DEBUG"):`, methods of your own named `set_trace` or `breakpoint`, test files.

## Remediation

1. Remove the breakpoint before release, and add a lint or pre-commit check (for example ruff `T100`).
2. Put any debugging aid that has to stay behind an explicit, off-by-default setting.
