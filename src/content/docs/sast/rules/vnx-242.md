## Overview

VNX-242 maps to [CWE-242: Use of Inherently Dangerous Function](https://cwe.mitre.org/data/definitions/242.html). It reports functions that cannot be called safely, because they write input of any length into a buffer they are given no size for:

- `gets()`, `std::gets()`, `_getws()`, `getws()`, `_getts()` and `getwd()`;
- C++ extraction with `operator>>` from `cin`, `wcin` or a variable declared as an `istream`, `ifstream`, `istringstream`, `stringstream` or `fstream` into a `char` or `wchar_t` array with no `std::setw()` before it (unbounded before C++20).

## Why this matters

There is no input for which these calls are safe: the caller cannot tell them how big the buffer is, so a long line overflows it and overwrites the stack. `gets()` was removed from C11 and C++14 for this reason.

Not reported: the bounded replacements (`fgets`, `gets_s`, `fgetws`, `getcwd`), method calls with the same name (`conn.gets()`, `p->gets()`), prototypes, `#define`/`#undef` lines, extraction into `std::string` or numbers, shift expressions, comments and string literals. `atoi`/`atol`/`atof` are not inherently dangerous (they are unsafe only on unvalidated input, CWE-676) and are not reported here.

## What gets flagged

```c
char name[64];
gets(name);
getwd(dir);
```

```cpp
char user[32];
std::cin >> user;
```

## Remediation

```c
if (fgets(name, sizeof name, stdin) == NULL)
    return 1;
getcwd(dir, sizeof dir);
```

```cpp
std::string user;
std::cin >> user;                    // or: std::cin >> std::setw(sizeof user) >> user;
```
