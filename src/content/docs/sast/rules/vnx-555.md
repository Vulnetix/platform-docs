## Overview

VNX-555 maps to [CWE-555: J2EE Misconfiguration: Plaintext Password in Configuration File](https://cwe.mitre.org/data/definitions/555.html). It reads Java EE deployment descriptors and application-server configuration and reports passwords written there in plain text.

## Why this matters

Descriptors are packaged into the WAR or EAR, committed to the repository and copied to every server. Anyone who can read one of those copies has the database, LDAP or SMTP credential, and rotating it means rebuilding and redeploying.

## What gets flagged

Files: `web.xml`, `context.xml`, `server.xml`, `tomcat-users.xml`, `persistence.xml`, `ejb-jar.xml`, `application.xml`, `ra.xml`, WildFly `standalone*.xml`/`domain.xml`/`host.xml`/`*-ds.xml`, GlassFish `glassfish-resources.xml`, `weblogic*.xml`, `jboss*.xml`, `jetty*.xml`, `resin.xml`, `ibm-*.xml`, `hibernate.cfg.xml`.

```xml
<Resource name="jdbc/AppDB" type="javax.sql.DataSource"
          username="app" password="S3cure!Pass"/>                                  <!-- FLAGGED -->
<user username="admin" password="tomcat123" roles="manager-gui"/>                 <!-- FLAGGED -->
<property name="jakarta.persistence.jdbc.password" value="Pr0dPassw0rd"/>         <!-- FLAGGED -->
<password>0racleApp</password>                                                    <!-- FLAGGED -->

<context-param>
  <param-name>dbPassword</param-name>
  <param-value>Winter2024!</param-value>                                          <!-- FLAGGED -->
</context-param>
```

Not flagged: empty values, references such as `${db.password}` and `#{env.DB_PASSWORD}`, encoded values (`{aes}...`, `{xor}...`, `ENC(...)`), masks and placeholder words, names that only contain the word (`hibernate.password.encoder`), XML comments, other XML files, `.example`/`.sample`/`.template` copies and test resources. VNX-260 reports passwords in configuration files generally and leaves the lines this rule reports in these files to it; VNX-SEC-014 reports `password="..."` attributes.

## Remediation

1. Define the data source or realm on the server with its credential store (Tomcat `${...}` property substitution, WildFly Elytron credential stores, WebSphere/WebLogic encrypted aliases) and reference it by JNDI name.
2. Read secrets from environment variables or a secrets manager at deploy time.
3. Rotate every password that was committed.

## Suppressing this rule

Put a `nosec` comment on the line, or on line 1 to cover the whole file. Use the comment marker of the file's language (`#`, `//`, `--` or `;`):

```text
# nosec vnx-555
// nosec vnx-555
```

Or record an ignore rule: `vulnetix ignore add --rule vnx-555 --reason "..."`. See [Suppressing findings](/sast/guides/suppressing-findings/).
