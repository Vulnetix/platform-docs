## Overview

VNX-598 maps to [CWE-598: Use of GET Request Method With Sensitive Query Strings](https://cwe.mitre.org/data/definitions/598.html). A query string is written to web server and proxy access logs, kept in browser history and sent onward in the `Referer` header.

The rule reports:

- a URL built in code whose query (the line opens one with `?name=`) carries a parameter named `password`, `passwd`, `pwd`, `pass`, `passphrase`, `secret`, `client_secret`, `api_key`, `apikey`, `api-key`, `access_token`, `auth_token`, `token`, `session_id`, `sessionid` or `ssn`, whose value is interpolated (concatenation, f-string or template-literal placeholder, `%s`/`%v`, PHP `$variable`);
- a GET helper (`requests.get`, `axios.get`, `http.get`) given such a key in its `params` object;
- an HTML or template `<form>` that submits a password input by GET: `method="get"`, or no method at all (GET is the default) in `.html`, `.htm`, `.php`, `.jsp`, `.ejs`, `.hbs`, `.twig`, `.jinja` and `.erb` files.

It does not report form-encoded POST bodies (`grant_type=password&password=...`), credentials in headers or POST data, constant example URLs (`?api_key=YOUR_API_KEY`), lookalike parameters (`pageToken`, `next_token`, `show_password_field`), `otpauth://` provisioning URIs, forms submitted by POST or by a script handler (`onsubmit`, `ngSubmit`, Angular bindings, `@submit`), or comments.

## What Gets Flagged

```python
url = f"{base}/login?user={username}&password={password}"            # FLAGGED
requests.get("https://api.example.com/v1/items?api_key=" + api_key)   # FLAGGED
requests.get(url, params={"q": q, "access_token": token})             # FLAGGED

# NOT FLAGGED
requests.get(url, headers={"X-Api-Key": api_key})
requests.post(base + "/token", data="grant_type=password&password=" + password)
```

```html
<form action="/session" method="get">      <!-- FLAGGED: has a password input -->
  <input type="password" name="pw">
</form>
```

## Remediation

1. Send credentials in a POST body or an `Authorization` header, never in the URL.
2. Give every login form `method="post"`.
3. Where an API only accepts a key in the query string, keep the URL out of logs and rotate the key.
