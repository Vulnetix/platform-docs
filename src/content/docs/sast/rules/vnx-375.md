## Overview

VNX-375 maps to [CWE-375: Returning a Mutable Object to an Untrusted Caller](https://cwe.mitre.org/data/definitions/375.html). It reports `return field;` or `return this.field;` in a public or protected method (one-line getters included) when the field is declared in the same file as an array or as `List`, `ArrayList`, `LinkedList`, `Map`, `HashMap`, `TreeMap`, `LinkedHashMap`, `Set`, `HashSet`, `TreeSet`, `LinkedHashSet`, `Collection`, `Deque`, `Queue`, `Date`, `Calendar` or `StringBuilder`.

Not reported: a returned copy or view (`Collections.unmodifiableList(x)`, `List.copyOf(x)`, `new ArrayList<>(x)`, `x.clone()`), fields initialised with an immutable value (`List.of`, `Set.of`, `Map.of`, `Collections.unmodifiable*`, `Collections.empty*`, `Immutable*`, `copyOf`), immutable field types, private and package-private methods, a local variable or parameter that shadows the field, JPA/document entities and JAXB-bound classes (whose collection getters the framework requires to be live), test sources and comments.

A public method with an array return type that returns a private, non-empty array field is reported by VNX-495, the array form of this weakness, and not here, so the line is not reported twice. This rule keeps collections, `Date`, `Calendar` and `StringBuilder`, protected methods, and arrays VNX-495 does not judge (protected or public fields, empty-array initialisers).

## Why this matters

A getter that hands out the field itself lets every caller change the object's internal state: clear a list the object relies on, overwrite a secret array, or move a stored date, all without the checks the object's own methods would apply.

## What gets flagged

```java
private final List<Item> items = new ArrayList<>();
public List<Item> getItems() {
    return items;                               // FLAGGED
}

public Set<String> getFlags() { return flags; } // FLAGGED

public Date getExpires() {
    return this.expires;                        // FLAGGED
}
```

Not flagged: `return Collections.unmodifiableList(items);`, `return secret.clone();`, `return new Date(expires.getTime());`, a field initialised with `List.of(...)`.

## Remediation

1. Return an unmodifiable view or a copy: `Collections.unmodifiableList(items)`, `List.copyOf(items)`, `array.clone()`.
2. Prefer immutable field types (`java.time.Instant` instead of `Date`).
