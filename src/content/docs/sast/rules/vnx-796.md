## Overview

VNX-796 maps to [CWE-796: Only Filtering Special Elements Relative to a Marker](https://cwe.mitre.org/data/definitions/796.html). It reports sanitising that removes special elements only at the beginning or end of a value:

- Python `str.strip`/`lstrip`/`rstrip` and lodash `_.trim`/`_.trimStart`/`_.trimEnd` whose character set mixes a dot with a path separator (`'./'`, `'../\\'`), or holds two or more shell metacharacters (`;`, `|`, `&`, `$`, a backtick), or one of them with a command (`exec`, `subprocess`, `os.system`...) within six lines
- Python `str.removeprefix`/`removesuffix` of a `..` sequence (`removeprefix('../')` removes one copy)
- Python `re.sub` and JavaScript `replace()` with an empty replacement whose pattern is anchored with `^` or `$` and removes dots with path separators (`^(\.\./)+`, `^[./\\]+`) or shell metacharacters (with the same two-or-command test)

Plain normalisation (`rstrip('/')`, `lstrip('.')`, `strip('"')`, `strip('<>')` on a Message-ID, `rstrip(';')` on an SQL statement, `strip('$')` on a price), stripping a file extension (`/\.[^/.]+$/`) and unanchored global replacements are not reported.

## Why This Matters

`'a/../../etc/passwd'.lstrip('./')` is unchanged, and `re.sub(r'^(\.\./)+', '', 'x/../../etc')` removes nothing. The filter only acts at the edge of the value, so the same sequence one character in survives.

## What Gets Flagged

```python
name = name.lstrip("./")                  # FLAGGED
return re.sub(r'^(\.\./)+', '', p)        # FLAGGED
arg = arg.rstrip(";|&")                   # FLAGGED
```

```javascript
const clean = name.replace(/^(\.\.\/)+/, '');   // FLAGGED
```

## Remediation

1. Resolve the joined path (`os.path.realpath`, `path.resolve`) and check it is under the base directory.
2. Validate the whole value against an allow-list rather than trimming its ends.
