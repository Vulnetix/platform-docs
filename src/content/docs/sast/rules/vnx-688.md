## Overview

VNX-688 maps to [CWE-688: Function Call With Incorrect Variable or Reference as Argument](https://cwe.mitre.org/data/definitions/688.html). The size argument names the wrong variable, usually after copy and paste: the call is bounded by another buffer's size, so a smaller destination overflows.

## What gets flagged

```c
char name[16];
char path[256];
snprintf(name, sizeof(path), "%s@%s", user, host);   // FLAGGED
strncpy(name, path, sizeof path);                    // FLAGGED: bounded by the source
read(fd, header, sizeof(body));                      // FLAGGED
std::snprintf(c->host, sizeof(c->url), "%s", u);     // FLAGGED: different struct members
```

Calls covered: `snprintf`, `vsnprintf`, `fgets`, `getcwd`, `gethostname`, `bzero`, `explicit_bzero`, `strncpy`, `strlcpy`, `strncat`, `strlcat`, `memset`, `memcpy`, `memmove`, `read`, `recv`, `recvfrom`, `pread` and `readlink`, when the destination and the array in `sizeof` are different arrays both declared in the file.

## What is not flagged

- A size taken from the destination itself.
- `memcpy`/`memmove` sized by the source array.
- `sizeof` of a type or of `*ptr`, and a pointer destination whose target is unknown.
- Calls split over several lines, comments and string literals.

## Remediation

Take the bound from the buffer being written: `snprintf(name, sizeof(name), ...)`.
