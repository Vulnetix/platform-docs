## Overview

VNX-770 maps to [CWE-770: Allocation of Resources Without Limits or Throttling](https://cwe.mitre.org/data/definitions/770.html). It reports configuration that switches off, or raises out of reach, a limit the framework applies to a single request.

**Python**

- Django `DATA_UPLOAD_MAX_MEMORY_SIZE`, `DATA_UPLOAD_MAX_NUMBER_FIELDS` or `DATA_UPLOAD_MAX_NUMBER_FILES` set to `None`
- Flask `MAX_CONTENT_LENGTH` assigned `None`
- Flask-Limiter turned off: `RATELIMIT_ENABLED = False`, `Limiter(..., enabled=False)`
- `sys.set_int_max_str_digits(0)`, which removes the guard against quadratic int/str conversion (CVE-2020-10735)

**Node**

- an express or body-parser `json`, `urlencoded`, `raw` or `text` parser with `limit: Infinity`, a gigabyte limit or one of 50 MB and more, or `parameterLimit: Infinity`
- `multer()` configured without a `limits` block
- a socket.io `maxHttpBufferSize` of `Infinity` or 100 MB and more

Not reported: bounded values, the frameworks' own defaults tables (dict literals such as Flask's `"MAX_CONTENT_LENGTH": None`), these settings inside a configuration class named for testing, development or local use, comments, string literals and test files. A limit that is simply never configured (no body parser options at all, no rate limiter) is not judged.

## Why this matters

These limits are what stop one client from making the server buffer a multi-gigabyte body in memory, parse millions of form fields, store unbounded uploads or burn CPU converting a huge integer. Removing them turns a single request into a denial of service.

## What gets flagged

```python
DATA_UPLOAD_MAX_MEMORY_SIZE = None                  # flagged
app.config['RATELIMIT_ENABLED'] = False             # flagged
sys.set_int_max_str_digits(0)                       # flagged
```

```javascript
app.use(express.json({ limit: '1gb' }))             // flagged
const upload = multer({ dest: 'uploads/' })         // flagged: no limits
```

Not flagged:

```javascript
app.use(express.json({ limit: '100kb' }))
const upload = multer({ dest: 'uploads/', limits: { fileSize: 2 * 1024 * 1024, files: 1 } })
```

## Remediation

Keep each limit at what the endpoint needs. For a route that genuinely accepts large uploads, raise the limit on that route only and stream the body to storage instead of buffering it.
