## Overview

`char` is signed on most platforms, and Java's `byte` always is. Bytes 0x80-0xFF therefore widen to negative `int` values. Passed to `isspace()` or `tolower()`, a negative value other than `EOF` is undefined behaviour and indexes the classification table out of bounds. Combined into a wider integer in Java, the sign bit smears across every upper bit, so `(b[0] << 8) | b[1]` returns a wrong (often negative) length. This maps to [CWE-194: Unexpected Sign Extension](https://cwe.mitre.org/data/definitions/194.html).

## What Gets Flagged

```c
const char *skip_ws(const char *p)
{
	while (isspace(*p))          /* flagged */
		p++;
	return p;
}
```

```java
public static int readLength(byte[] header) {
    return (header[0] << 8) | header[1];   // flagged
}
```

The declaration nearest the call decides the type, so a `char c` in another function does not affect an `int c` here. Not flagged: arguments cast to `(unsigned char)`, variables declared `unsigned char` or `int` (a `getc()` result), masked bytes (`b[i] & 0xff`, `Byte.toUnsignedInt`), an unmasked byte shifted by 24 into the top of an `int`, arrays of other types, and comments.

## Remediation

```c
while (isspace((unsigned char)*p))
	p++;
int lower = tolower((unsigned char)c);
```

```java
return ((header[0] & 0xff) << 8) | (header[1] & 0xff);
```
