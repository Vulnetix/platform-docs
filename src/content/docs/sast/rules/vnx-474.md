## Overview

VNX-474 maps to [CWE-474: Use of Function with Inconsistent Implementations](https://cwe.mitre.org/data/definitions/474.html). Reports C/C++ calls whose behaviour differs between platforms in a way that changes correctness: signal() installing a handler (once per file), strerror_r() outside a variant-selecting #if, realloc(p, 0), the MSVC _snprintf/_vsnprintf family, and vfork(). SIG_IGN/SIG_DFL, sigaction, snprintf, fork, test sources and comments are not reported.

## Why this matters

This weakness class (Use of Function with Inconsistent Implementations) creates a concrete exploit surface: the rule searches for the concrete source-level patterns most commonly associated with CWE-474 and surfaces them for review. Each finding should be evaluated in context, the rule catches the pattern, not the context.

## What gets flagged

```c
// FLAGGED: System V resets the handler after one delivery, BSD does not
signal(SIGINT, on_interrupt);

// FLAGGED: GNU strerror_r may not write buf at all
strerror_r(errno, c->errstr, sizeof(c->errstr));

// FLAGGED: frees on some libraries, allocates on others
v->items = realloc(v->items, 0);

// NOT FLAGGED: consistent everywhere
signal(SIGPIPE, SIG_IGN);
sigaction(SIGHUP, &sa, NULL);
```

## Remediation

1. Review each flagged line and determine whether the pattern represents a real instance of CWE-474 or a false positive.
2. Replace the flagged construct with a documented safe alternative appropriate to your language and framework.
3. For confirmed false positives, add a `# vulnetix-ignore: VNX-474` comment on the line.
4. Ensure equivalent test coverage exists to prevent regression.
