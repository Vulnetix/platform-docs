## Overview

VNX-710 maps to [CWE-710: Improper Adherence to Coding Standards](https://cwe.mitre.org/data/definitions/710.html). It reports the one form of that weakness a scanner can recognise: source code that turns off a warning written to catch memory-safety, uninitialised-value or format-string defects. That covers `#pragma warning(disable|suppress: ...)` for C4996, C4789, C4700, C4701, C4703, C6385, C6386, C6387 or C6011, and `#pragma GCC|clang diagnostic ignored` for `-Wformat-security`, `-Wformat-nonliteral`, `-Wformat-overflow`, `-Wformat-truncation`, `-Wstringop-*`, `-Warray-bounds`, `-Wuninitialized`, `-Wmaybe-uninitialized`, `-Wreturn-local-addr`, `-Wreturn-stack-address`, `-Wfree-nonheap-object`, `-Wuse-after-free` and `-Wdangling-pointer`. It also covers the `__pragma(...)` and `_Pragma("...")` macro spellings of those directives, and `#define _CRT_SECURE_NO_WARNINGS` or `_CRT_SECURE_NO_DEPRECATE`.

## What gets flagged

```c
#pragma warning(disable: 4996)                     // FLAGGED
#pragma GCC diagnostic ignored "-Wformat-security" // FLAGGED
#define _CRT_SECURE_NO_WARNINGS                    // FLAGGED
```

Not reported: style and portability warnings such as `-Wunused-parameter`, `-Wsign-compare`, `-Wdeprecated-declarations`, C4100 and C4244. Also not reported: `#pragma warning(push|pop|default|error: ...)`, flags in build files, comments and strings. A directive written with spaces between `#` and `pragma` (`#  pragma`) is not reported, because the engine reads that line as a comment.

## Remediation

1. Fix the code the warning reports. Replace `strcpy`/`sprintf` with bounded calls, and pass a constant format string.
2. If a suppression cannot be avoided, keep it to one audited line (`#pragma warning(suppress: ...)` or `push`/`pop`) and record why.
