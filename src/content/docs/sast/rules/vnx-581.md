## Overview

VNX-581 maps to [CWE-581: Object Model Violation: Just One of Equals and Hashcode Defined](https://cwe.mitre.org/data/definitions/581.html). Objects that are equal must have equal hash codes. A class that overrides only one of the two breaks that contract: `HashMap`, `HashSet` and caches miss entries, store duplicates, or fail to find a key that is present. That can defeat de-duplication, permission sets and lookups keyed by the object.

## What gets flagged

The line declaring the lone method: `public boolean equals(Object)` or `public int hashCode()` in Java, and `override fun equals(other: Any?)` or `override fun hashCode()` in Kotlin. The pairing is judged per class, so a nested class that defines only one is reported even when its outer class defines both.

```java
public class Sku {
    @Override
    public boolean equals(Object o) {
        ...
    }
    // no hashCode()
}
```

```kotlin
class Version(val major: Int, val minor: Int) {
    override fun equals(other: Any?): Boolean { ... }
    // no hashCode()
}
```

## What is not flagged

- A class that defines both.
- A Kotlin `data class` or Java `record`, whose other method the compiler generates over the same components.
- An `equals` overload with another parameter type (`equals(Range r)`), which is a different mistake.
- Calls of `hashCode()` or `equals()` on other objects.
- Test code, comments and string literals.

## Remediation

1. Override both, over the same fields: `Objects.equals(...)` in `equals`, `Objects.hash(...)` in `hashCode`.
2. In Kotlin, a `data class` derives both from its properties.
