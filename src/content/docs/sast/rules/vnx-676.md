## Overview

VNX-676 maps to [CWE-676: Use of Potentially Dangerous Function](https://cwe.mitre.org/data/definitions/676.html). The classic C string functions write as much as their input holds into a buffer they are given no size for. The rule reports them in the forms that can actually overflow:

- `gets()` and `_getws()`: always.
- `strcpy`, `stpcpy`, `strcat`, `wcscpy`, `wcscat` (also `std::`): when the source is not a string literal, an upper-case macro or a choice between literals, and neither was its length measured (`strlen`/`wcslen`/`strnlen`) nor the destination's `sizeof` compared in an `if`/`assert` in the 15 lines above.
- `sprintf` with a literal format containing `%s`/`%ls` without precision; `vsprintf` always.
- `scanf`, `fscanf`, `sscanf`, the `v` and wide forms, with `%s`, `%ls` or `%[` and no field width.

Calls that wrap over several lines are read across them.

## What gets flagged

```c
gets(line);                                       /* FLAGGED */
strcpy(name, user);                               /* FLAGGED */
sprintf(out, "hello %s, you have %d", who, n);    /* FLAGGED */
scanf("%s", word);                                /* FLAGGED */
```

## What is not flagged

- `fgets`, `strncpy`, `strlcpy`, `strncat`, `snprintf`, `vsnprintf` and the `_s` functions.
- `%.20s`, `%15s`, `%*s` and `%ms`; `sprintf` with only numeric conversions or a non-literal format.
- `strcpy(c->name, "default")`, `strcpy(p, s)` after `malloc(strlen(s) + 1)`.
- Prototypes, `#define` lines, methods and lookalike names (`b.strcpy`, `p->gets`, `my_strcpy`), comments and string literals.

VNX-C-001 reports the same copies (with more Windows variants), and VNX-242 reports `gets()`.

## Remediation

```c
fgets(line, sizeof line, stdin);
snprintf(name, sizeof name, "%s", user);
scanf("%31s", word);
```
