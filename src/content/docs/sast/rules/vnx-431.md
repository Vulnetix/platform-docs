## Overview

VNX-431 maps to [CWE-431: Missing Handler](https://cwe.mitre.org/data/definitions/431.html). An error that something is expected to handle has no handler at all. In a servlet application, an uncaught exception then reaches the container's default error page, which shows the stack trace and server version. In concurrent code, an exception thrown by a task whose future nobody keeps is captured in that future and never seen.

## What gets flagged

- A `web.xml` whose `<web-app>` has no `<error-page>` for `java.lang.Throwable`/`Exception`/`RuntimeException`, none for error code 500, and no default `<error-page>` with only a `<location>` (the `<web-app>` line is reported).
- `CompletableFuture.runAsync`/`supplyAsync` used as a statement (future not assigned, returned or passed on) whose chain has no `exceptionally`, `handle`, `whenComplete`, `join` or `get`.
- `executor.submit(...)` used as a statement, where `executor` is declared as an `ExecutorService`, `ScheduledExecutorService`, `ThreadPoolExecutor` or `ForkJoinPool`, or assigned from `Executors.*`.

```java
CompletableFuture.runAsync(() -> store.save(r.rebuild()), pool);   // FLAGGED
workers.submit(() -> smtp.deliver(m));                             // FLAGGED

CompletableFuture.runAsync(task, pool).exceptionally(ex -> { log.error("failed", ex); return null; });  // not flagged
pool.execute(task);                                                // not flagged: reaches the uncaught-exception handler
```

```xml
<web-app ...>          <!-- FLAGGED when no error page covers uncaught exceptions -->
  <error-page>
    <exception-type>java.lang.Throwable</exception-type>
    <location>/error</location>
  </error-page>        <!-- with this, not flagged -->
</web-app>
```

Not reported: a task whose body catches `Exception` or `Throwable`, a kept future, `execute()`, test sources, comments. A broad `@ExceptionHandler(Exception.class)` is a handler and is not reported. The rule is evaluated only when the scanned tree also contains Java source, so a web.xml scanned alone, with no .java file beside it, is not read.

## Remediation

1. Declare `<error-page>` entries for `java.lang.Throwable` (and 500) pointing at a generic page.
2. Keep the future and attach `exceptionally`/`handle`/`whenComplete`, or catch inside the task.
3. Use `execute()` for fire-and-forget work so the thread's uncaught-exception handler sees failures.
