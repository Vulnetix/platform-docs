## Overview

VNX-1391 maps to [CWE-1391: Use of Weak Credentials](https://cwe.mitre.org/data/definitions/1391.html). A password from the top of every guessing wordlist falls to the first minutes of a brute-force or credential-spraying attempt. The rule reports a password-named key (ending in `password`, `passwd`, `pwd`, `passphrase` or `_pass`) whose value is an all-digit string of four or more digits, a keyboard walk (`qwerty`, `asdf`, `1q2w3e4r`), a common wordlist entry (`letmein`, `welcome`, `iloveyou`, `trustno1`, `abc123`), or a default word with a short suffix (`password123`, `p@ssw0rd`, `admin123`, `admin321`, `root1`).

## What Gets Flagged

```python
ADMIN_PASSWORD = "123456"
db.create_user(email="ops@example.org", password="qwerty")
SMTP_PASSWORD = os.environ.get("SMTP_PASSWORD", "abc123")
```

```javascript
cachePass: process.env.CACHE_PASSWORD || "1q2w3e4r",
```

```yaml
environment:
  - REDIS_PASSWORD=admin321
  MYSQL_PASSWORD: qwerty123
```

Not flagged: bare vendor defaults (`password`, `admin`, `changeme`, ...; VNX-1393), a weak password set for a default account (`email: admin` above `password: admin123`, `MYSQL_ROOT_PASSWORD=admin321`, `User Id=sa;Password=123456`), which is reported by VNX-1392 as a default credential pair so the line is reported once, strong or random literals, hashes, comparisons (`password === "123456"`), text inside a longer string or a comment, test code and config templates (`.env.sample`). Password-length policies are VNX-521.

## Remediation

1. Generate a long random secret per deployment and inject it from a secrets manager or the environment.
2. For seeded accounts, generate the password at install time and force a change at first login.
3. Reject wordlist passwords at sign-up (for example against a breached-password list).
