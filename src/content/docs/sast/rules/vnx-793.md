## Overview

VNX-793 maps to [CWE-793: Only Filtering One Instance of a Special Element](https://cwe.mitre.org/data/definitions/793.html). It reports sanitising that removes or rewrites only the first occurrence of a special element:

- JavaScript/TypeScript `String.replace()` with a string literal, or a regex literal without the `g` flag, whose pattern is a `..`, `../`, `..\` or `\.\.[\/\\]` traversal sequence, a shell metacharacter (`&&`, `||`, a backtick, `$(`; and `;`, `|`, `$` or a deleted `&` when a command such as `exec`, `subprocess` or `cmd` appears within six lines), CR/LF or a NUL byte
- Python `str.replace(..., 1)` and `re.sub(..., count=1)` with the same tokens

A lone `$`, `|` or `;` far from any command (a price, a table cell, a CSS value) is not reported.

Global replacements (reported by VNX-791 when they delete the token), anchored patterns (VNX-796) and markup tokens (VNX-792) are not reported.

## Why This Matters

`'../../etc/passwd'.replace('../', '')` is `../etc/passwd`. Any input that repeats the element keeps all but the first occurrence, so the filter only stops payloads that never repeat.

## What Gets Flagged

```typescript
relativePath = relativePath.replace('..', '.')            // FLAGGED
const h = host.replace(';', '').replace('|', '');         // FLAGGED: exec() follows
res.setHeader('Location', target.replace('\r\n', ''));    // FLAGGED
return p.replace(/\.\.\//, '');                           // FLAGGED: no g flag
```

## Remediation

1. Resolve paths and check the result stays under the base directory instead of editing the string.
2. Run commands with an argument list and no shell.
3. Reject header values that contain CR or LF.
