## Overview

VNX-652 maps to [CWE-652: Improper Neutralization of Data within XQuery Expressions](https://cwe.mitre.org/data/definitions/652.html). In Java files that use an XQuery API (`javax.xml.xquery`, `net.sf.saxon`, `org.basex`, `org.xmldb`, `com.marklogic.xcc`) it reports `executeQuery`, `prepareExpression`, `executeCommand`, `compile`, `query`, `execute`, `newAdhocQuery`, `new XQuery(...)` and `new QueryProcessor(...)` whose argument:

- concatenates a variable, parameter or method result into a string literal,
- uses `String.format`, `.formatted` or `MessageFormat.format`, or
- is a variable or `StringBuilder.toString()` built that way in the ten lines above (including a concatenation broken across lines).

Not reported: external variables bound with `bindString`/`bindObject`, constant queries and concatenation of literals or `UPPER_CASE` constants, SQL passed to JDBC, files without an XQuery API, comments and the call inside a string literal.

## Why this matters

A value such as `' or '1'='1` or `'] | doc('secrets.xml')//*[' ` rewrites the query, returning documents the caller should not see, and with some engines (BaseX, MarkLogic) reaching file and HTTP functions.

## What gets flagged

```java
// FLAGGED
return expr.executeQuery("for $b in doc('books.xml')//book where $b/author = '" + req.getParameter("author") + "' return $b");

String query = "doc('users.xml')/users/user[name='" + username + "']";
XQPreparedExpression pe = conn.prepareExpression(query);      // FLAGGED

return compiler.compile(String.format("//sale[region='%s']", region));   // FLAGGED
```

```java
// NOT FLAGGED: external variable
XQPreparedExpression pe = conn.prepareExpression("declare variable $author external; //book[author = $author]");
pe.bindString(new QName("author"), author, null);
```

## Remediation

1. Declare `external` variables in the query and bind values (`bindString`, Saxon `XQueryEvaluator.setExternalVariable`, BaseX `bind`).
2. Never build the query text from request data.
