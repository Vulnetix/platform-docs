## Overview

VNX-1022 maps to [CWE-1022: Use of Web Link to Untrusted Target with window.opener Access](https://cwe.mitre.org/data/definitions/1022.html). It reports:

- an `<a>`, `<area>`, `<form>`, `<Link>` or `<NavLink>` with `target="_blank"` whose URL comes from an expression (JSX `{expr}`, Vue `:href`, Angular `[href]`, Thymeleaf `th:href="${...}"`, or a value starting with `{{ }}`, `<%= %>`, `<?= ?>`, `${ }` or Razor `@`) and no `rel` containing `noopener` or `noreferrer`;
- any such tag with `rel="opener"`;
- `window.open(url, ...)` with a non-constant URL, no `noopener`/`noreferrer` feature and no `.opener = null` on the result.

Not reported: links and `window.open` calls with a fixed URL or a fixed host and an interpolated path (current browsers apply noopener to `target="_blank"` anchors by default, and a fixed link names a site the author chose), relative links and template route helpers (`{{ url_for(...) }}`, `{{ path(...) }}`, `{% url %}`, `*_path`, Hugo `.Permalink`/`.RelPermalink`, Jekyll `site.baseurl`), `window.open` to `_self`/`_parent`/`_top`, comments and test files.

## Why this matters

A page opened with `window.opener` access can set `window.opener.location` and quietly replace the original tab with a phishing copy of it while the user is looking at the new tab. When the URL comes from user content (a profile website, a shared link), the attacker controls the opened page.

## What gets flagged

```jsx
<a href={user.website} target="_blank">Website</a>
```

```html
<a href="{{ post.source_url }}" target="_blank">{{ post.source }}</a>
<a href="https://partner.example/" target="_blank" rel="opener">Partner</a>
```

```typescript
window.open(target, '_blank');
```

## Remediation

1. Add `rel="noopener noreferrer"` to every `target="_blank"` link whose URL is not fixed.
2. Pass `'noopener,noreferrer'` as the third argument of `window.open`, or set `newWindow.opener = null`.
3. Never use `rel="opener"` for a link to another origin.
