## Overview

VNX-279 maps to [CWE-279: Incorrect Execution-Assigned Permissions](https://cwe.mitre.org/data/definitions/279.html): while it runs, the product sets the permissions of an object in a way nobody intended. CWE-279 is abstract, so this rule reports its most concrete and most dangerous form: assigning the **setuid bit**. Whoever executes a setuid file does so with the identity of its owner, usually root, so any flaw in that file, or the ability to replace it, becomes a privilege escalation.

Reported:

- C, C++: `chmod`, `fchmod`, `fchmodat`, `lchmod` with a `04xxx`-`07xxx` mode or `S_ISUID`, and `std::filesystem::permissions` with `perms::set_uid`.
- Python: `os.chmod`, `os.fchmod`, `Path.chmod` with `0o4xxx` or `stat.S_ISUID`.
- Go: `os.Chmod`/`File.Chmod` with `os.ModeSetuid`, and `syscall`/`unix` `Chmod` with a setuid mode.
- PHP: `chmod($f, 04755)`. JavaScript/TypeScript: `fs.chmod`/`chmodSync` with `0o4755` or `"4755"`. Ruby: `File.chmod(04755, f)`, `FileUtils.chmod("u+s", f)`. Rust: `fs::Permissions::from_mode(0o4755)` or `set_mode(0o4755)`.
- Ansible: `mode: '4755'` or `mode: u+s` in `file`/`copy`/`template` tasks.
- Shell scripts and Dockerfiles: `chmod u+s`, `chmod +s`, `chmod a+s`, `chmod 4755`, `install -m 4755`, `COPY --chmod=4755`.
- The same `chmod` command run through `system`, `subprocess`, `os.system`, `exec.Command`, `execSync` or `shell_exec`, and a mode held in a variable assigned such a literal just above.

## What gets flagged

```c
chmod(helper, 04755);                     // FLAGGED
chmod(path, st.st_mode | S_ISUID);        // FLAGGED
```

```python
os.chmod(path, os.stat(path).st_mode | stat.S_ISUID)   # FLAGGED
```

```dockerfile
RUN chmod u+s /usr/bin/find               # FLAGGED
```

## What is not flagged

- Setgid alone (`chmod g+s dir`, `02775`): on a directory it is the normal way to share a group.
- Clearing or testing the bit: `st.st_mode & ~S_ISUID`, `fi.Mode() &^ os.ModeSetuid`, `chmod u-s`, `chmod a-s`, `if (st.st_mode & S_ISUID)`, `find / -perm -4000`.
- Ordinary and sticky modes (`0755`, `01777`).
- Go `os.Chmod(p, 0o4755)`: Go's `os.FileMode` does not map the `04000` bit to setuid, so this call does not set it (`os.ModeSetuid` does).
- Test code and the pattern in comments or strings.

## Remediation

Avoid setuid files. Give the program the single capability it needs (`setcap cap_net_bind_service=+ep`), or run the privileged part as a separate service or through a reviewed sudoers or polkit rule. In container images, remove setuid bits rather than adding them:

```dockerfile
RUN find / -xdev -perm /6000 -type f -exec chmod a-s {} \; || true
```
