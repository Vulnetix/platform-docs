## Overview

VNX-487 maps to [CWE-487: Reliance on Package-level Scope](https://cwe.mitre.org/data/definitions/487.html). It reports credentials kept in package-private (default access) fields, where package scope is the only barrier between the secret and other code.

## Why this matters

A Java package is not a security boundary. Any class that declares `package com.acme.auth;`, including one in another jar on the class path, can read a package-private field. A password or key left at default access is readable by far more code than its author intended.

## What gets flagged

```java
public class TokenStore {
    String apiToken;                          // FLAGGED
    char[] masterPassword;                    // FLAGGED
    static String adminPassword = System.getenv("ADMIN_PW");  // FLAGGED
    SecretKey sessionKey;                     // FLAGGED (key type, any name)
    private String hidden;                    // not flagged
    static final String PASSWORD_PARAM = "password";  // not flagged: names a parameter
}
```

## Remediation

1. Declare the field `private` and expose only the operation callers need (sign, verify), not the secret.
2. Clear `char[]`/`byte[]` secrets after use.
3. If the package must stay closed, seal it in the jar manifest (`Sealed: true`) or use JPMS modules that do not export it.
