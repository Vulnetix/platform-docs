## Overview

VNX-457 maps to [CWE-457: Use of Uninitialized Variable](https://cwe.mitre.org/data/definitions/457.html). It reports a function-local scalar (int, long, char, double, size_t, intN_t, bool...) declared without an initialiser, at its first mention within the next 25 lines of the same block, when that mention reads the value: `return v`, `v++`, a compound assignment, the right-hand side of an assignment, an if/while/switch condition, a printf-family argument or `std::cout << v`. A local char array is reported when its first use is strcat/strncat/strlen/strdup/puts or a printf argument. A first mention that assigns, takes the address (`&v`, scanf) or passes the variable to a call that may fill it is not reported, nor are static, namespace-scope and struct/class members.

## Why this matters

An uninitialised local holds whatever was on the stack. Accumulators start from garbage, status codes return stale values, and a string buffer without a terminator lets strcat walk off the end of the array.

## What gets flagged

```c
// FLAGGED: accumulator never zeroed
long total;
for (i = 0; i < n; i++) {
    total += samples[i];
}

// FLAGGED: buffer appended to before it holds a string
char path[256];
strcat(path, dir);

// NOT FLAGGED: assigned on every branch first
int r;
if (x > 100) r = 100; else r = x;
return r;
```

## Remediation

1. Initialise locals at the declaration (`long total = 0;`, `char path[256] = "";`).
2. Enable compiler warnings (`-Wall -Wuninitialized -Wmaybe-uninitialized`) and sanitizers (MSan) for the paths a line-oriented rule cannot follow.
3. For confirmed false positives, add a `// vulnetix-ignore: VNX-457` comment on the line.
