## Overview

VNX-384 maps to [CWE-384: Session Fixation](https://cwe.mitre.org/data/definitions/384.html). It reports:

- Spring Security configured to keep the pre-login session: `sessionFixation().none()`, `sessionFixation(f -> f.none())`, `SessionFixationConfigurer::none`, and `session-fixation-protection="none"` in XML;
- a servlet or controller method that checks credentials (it mentions a password, `authenticate`, `checkPassword`, `login` or credentials) and then stores the identity in the existing session (`setAttribute` with a key such as `user`, `userId`, `loggedIn`, `principal`, `role`, or a constant such as `SESSION_USER`) without calling `session.invalidate()` or `request.changeSessionId()` earlier in the method.

Not reported: `migrateSession()`, `newSession()` and `changeSessionId()` configuration (Spring's default protects), a method that rotates or invalidates the session first, attributes unrelated to identity (cart, locale), methods that check no credentials, comments, string literals and test code.

## Why this matters

If the session id stays the same across login, an attacker who planted a known id in the victim's browser (through a link, a subdomain cookie or a shared machine) is logged in as the victim the moment the victim signs in.

## What gets flagged

```java
http.sessionManagement().sessionFixation().none();               // FLAGGED

if (users.checkPassword(name, password)) {
    HttpSession session = req.getSession();
    session.setAttribute("user", user);                          // FLAGGED
}
```

```xml
<session-management session-fixation-protection="none"/>        <!-- FLAGGED -->
```

Not flagged: `req.changeSessionId();` or `req.getSession().invalidate();` before the `setAttribute`, `sessionFixation().migrateSession()`, `session.setAttribute("cart", cart)`.

## Remediation

1. Keep Spring Security's default (`changeSessionId`) or use `migrateSession()`.
2. In servlet code, call `request.changeSessionId()` (or invalidate the old session and create a new one) immediately after the credentials are verified and before storing the user.
