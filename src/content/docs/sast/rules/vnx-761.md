## Overview

VNX-761 maps to [CWE-761: Free of Pointer not at Start of Buffer](https://cwe.mitre.org/data/definitions/761.html). It reports `free(p + n)`, `free(s->data + s->off)`, `free(&buf[i])` with a non-zero index and `free(++p)`, and a local pointer that was assigned from `malloc`, `calloc`, `realloc`, `strdup` or `strndup`, advanced in the same function (`p++`, `*p++ = c`, `p += n`), and then freed without being reset.

It does not report `free(ptr - HEADER)` (the allocator-wrapper idiom), a separate cursor that walks the buffer while the original pointer is freed, `free(items[i])`, `free(&buf[0])` or wrapper functions such as `sdsfree`.

## Why This Matters

`free()` must receive exactly the pointer the allocator returned. An interior pointer makes the allocator read a chunk header from the wrong place, which corrupts the heap and can be turned into an arbitrary write.

## What Gets Flagged

```c
free(packet + hdr);          // flagged
free(&buf[4]);               // flagged

char *line = strdup(in);
while (isspace(*line))
    line++;
free(line);                  // flagged
```

## Remediation

1. Keep the original pointer and walk the buffer with a separate cursor (`char *p = buf; ... free(buf);`).
2. Free only the pointer that `malloc`, `calloc`, `realloc` or `strdup` returned.
