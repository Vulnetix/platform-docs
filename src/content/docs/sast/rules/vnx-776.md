## Overview

VNX-776 maps to [CWE-776: Improper Restriction of Recursive Entity References in DTDs ('XML Entity Expansion')](https://cwe.mitre.org/data/definitions/776.html). It reports XML parsing that expands nested internal entities without a limit:

- Python `xml.etree.ElementTree` / `cElementTree` (`fromstring`, `XML`, `parse`, `iterparse`, `fromstringlist`), `xml.dom.minidom` and `pulldom` (`parse`, `parseString`), `xml.sax` and `xmltodict.parse`, under any alias, when given request data, an upload stream, stdin, `urlopen()` or a `requests` response, directly or through a variable assigned from one up to 25 lines above
- lxml `XMLParser(huge_tree=True)`, PHP `LIBXML_PARSEHUGE`, libxmljs `huge: true` and libxml2-wasm `XML_PARSE_HUGE`, which switch libxml2's expansion limits off

Not reported: defusedxml (or a file calling `defusedxml.defuse_stdlib()`), parsers given a constant, a local path or a parameter of unknown origin, lxml with its default limits, Java factories (VNX-JAVA-024) and external entity resolution (XXE).

## Why this matters

A few kilobytes of nested entity definitions ("billion laughs", quadratic blowup) expand to gigabytes in memory, so one request exhausts the worker's memory and CPU.

## What gets flagged

```python
root = ET.fromstring(request.data)            # FLAGGED
dom = minidom.parseString(request.body)       # FLAGGED
parser = etree.XMLParser(huge_tree=True)      # FLAGGED
```

```php
$doc->loadXML($xml, LIBXML_PARSEHUGE);        // FLAGGED
```

Not flagged:

```python
from defusedxml import ElementTree as ET
root = ET.fromstring(request.data)
```

## Remediation

1. Parse untrusted XML in Python with `defusedxml`, or with lxml at its default limits.
2. Remove `huge_tree=True`, `LIBXML_PARSEHUGE`, `huge: true` and `XML_PARSE_HUGE` from code that parses untrusted input.
