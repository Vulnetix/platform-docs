## Overview

VNX-243 maps to [CWE-243: Creation of chroot Jail Without Changing Working Directory](https://cwe.mitre.org/data/definitions/243.html). It reports a chroot call that is not followed, in the same function and within 20 lines, by a change of working directory: C/C++ `chroot()`, Python `os.chroot()` (or `chroot` imported from `os`), Go `syscall.Chroot()`/`unix.Chroot()`, Rust `fs::chroot()`/`nix::unistd::chroot()` and Ruby `Dir.chroot()`, with no `chdir()`/`fchdir()`, `os.chdir()`, `os.Chdir()`, `std::env::set_current_dir()` or `Dir.chdir` after it.

## Why this matters

`chroot()` changes what `/` means but not the current directory. A process whose working directory is still outside the new root can open `../../etc/shadow` and leave the jail with relative paths.

Not reported: a `chdir` after the `chroot`, the `chdir(dir); chroot(".")` idiom and `chdir(dir); chroot(dir)` with the same argument, method calls and wrappers (`o->chroot()`, `my_chroot()`), prototypes, comments and string literals. A `chdir` before the `chroot` to a different directory does not count, nor does a `chdir` after it to a relative literal path (`chdir("work")` moves relative to the old directory, which is still outside the jail). A Go `SysProcAttr` `Chroot` field for a child process is not judged.

## What gets flagged

```c
if (chroot(dir) != 0) {
    perror("chroot");
    return -1;
}
setuid(65534);
```

```python
os.chroot(jail)
os.setuid(65534)
```

## Remediation

```c
if (chroot(dir) != 0 || chdir("/") != 0)
    return -1;
```

```go
if err := unix.Chroot(dir); err != nil {
	return err
}
return os.Chdir("/")
```
