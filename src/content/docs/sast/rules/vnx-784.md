## Overview

VNX-784 maps to [CWE-784: Reliance on Cookies without Validation and Integrity Checking in a Security Decision](https://cwe.mitre.org/data/definitions/784.html). It reports a raw cookie read whose name says it carries a privilege or a login state (`admin`, `is_admin`, `role`, `user_role`, `staff`, `superuser`, `access_level`, `user_type`, `logged_in`, `authenticated`, `permissions` and similar) when the value is compared or tested on the same line, or assigned to a variable that a condition uses within the next 15 lines.

Raw reads covered: Django/Flask `request.COOKIES` / `request.cookies` (and `"logged_in" not in request.COOKIES`), Bottle/Tornado `get_cookie()` without `secret=`; Express `req.cookies` (including destructuring), Koa `ctx.cookies.get()` without `signed: true`, Next.js `cookies().get()`; PHP `$_COOKIE` and `filter_input(INPUT_COOKIE, ...)`, including an `if (!isset($_COOKIE[...logged_in...]))` gate; Rails `cookies[...]`; Spring `@CookieValue` and servlet `Cookie.getName()`/`getValue()`; Go `r.Cookie()` (also tested in the same `if` statement); ASP.NET `Request.Cookies[...]`.

Not reported: signed or encrypted cookie APIs (`req.signedCookies`, `cookies.signed`/`cookies.encrypted`, `get_signed_cookie`, `get_secure_cookie`), server-side sessions, preference, consent and session-id cookies, a role cookie that is only displayed, an `isset()` check whose block only sets the cookie, and code that writes cookies.

## Why this matters

The browser controls every cookie. A user who edits `admin=0` to `admin=1` grants themselves the role the check is protecting.

## What gets flagged

```python
if request.COOKIES.get("admin") == "1":         # FLAGGED
    return render_admin(request)
```

```javascript
const { role } = req.cookies;                   // FLAGGED
if (role === "admin") deleteUser(req.params.id);
```

Not flagged:

```javascript
if (req.session.role === "admin") return next();
```

## Remediation

1. Keep roles and login state on the server (session store, database) and look them up from an authenticated session.
2. If a cookie must carry a claim, sign or encrypt it (`cookies.signed`, `req.signedCookies`, a verified JWT) and verify it before use.
