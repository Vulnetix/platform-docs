## Overview

VNX-824 maps to [CWE-824: Access of Uninitialized Pointer](https://cwe.mitre.org/data/definitions/824.html). It reports a local pointer declared without an initialiser (`char *p;`, `struct node *n;`, `std::string *s;`) whose first mention in the same function, within 40 lines, dereferences it: `*p`, `p->field`, `p[i]`, a buffer argument of `strcpy`/`strncpy`/`strcat`/`memcpy`/`memmove`/`memset`/`sprintf`/`snprintf`/`fgets`/`gets`/`read`/`recv`/`fread`/`strlen`/`strcmp`/`printf`/`puts`/`free`, or `delete p`.

Not reported: a first mention that assigns the pointer (`p = malloc(...)`, `for (p = head; ...)`, `if ((p = f()) == NULL)`), takes its address (`getaddrinfo(..., &res)`, `getline(&line, ...)`), or only tests it; pointers with an initialiser; static, extern and file-scope pointers (zero-initialised); struct, union and class members; K&R parameter declarations and lines that continue an expression from the line above; declarations listing several pointers; flow through other functions; comments and string literals. Uninitialised scalars and arrays are VNX-457.

## Why this matters

An uninitialised local pointer holds whatever the stack held before. Writing through it corrupts an arbitrary address; reading through it leaks or crashes. Because the stale value depends on earlier calls, the bug often works in tests and fails in production.

## What gets flagged

```c
char *p;
strcpy(p, who);          /* FLAGGED: p was never given an address */

struct node *n;
n->value = value;        /* FLAGGED */
```

## Remediation

1. Initialise every pointer at its declaration (`char *p = NULL;`) and assign it a real object before use.
2. Allocate or point at a buffer before copying into it.
