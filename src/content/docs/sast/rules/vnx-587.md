## Overview

VNX-587 maps to [CWE-587: Assignment of a Fixed Address to a Pointer](https://cwe.mitre.org/data/definitions/587.html). It reports a cast of an integer literal to a pointer type (C casts and `reinterpret_cast`) that is assigned to a pointer, returned, or bound by a `#define`, including a cast whose literal is on the next line.

## Why This Matters

A hard-coded address ties the program to one memory layout. When the layout changes (another board revision, ASLR, a different loader), the pointer refers to unrelated or unmapped memory, which corrupts data or crashes, and a predictable address helps an attacker.

## What Gets Flagged

```c
int *p = (int *)0x8000;
reg = (uint8_t *)0xFFFF0000u;
#define UART0_DR (*(volatile unsigned int *)0x4000C000)
```

```cpp
auto *ctrl = reinterpret_cast<std::uint32_t *>(0x1F000000);
```

Not flagged: `(void *)0`, `(char *)-1`, `(void *)0x100` and other values below the first page, `0xFFFFFFFF`, poison values such as `0xdeadbeef`, `(uintptr_t)0x40020000`, `(uint32_t *)(base + 0x4000)`, `child == (void *)0x40020000`, casts passed as arguments, comments, strings and test files.

## Remediation

1. Take device addresses from the platform's headers, linker map or device tree rather than literals scattered through the code.
2. On hosted systems, obtain memory from `mmap()` or the allocator and never assume an absolute address.
