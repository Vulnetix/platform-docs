An organisation or user account the Software Factory manages: the switch on the Factory organisations page. The account must already be connected, through the Vulnetix GitHub App or a forge connection, and active. Which of its repositories the App can reach is chosen on GitHub when the App is installed; this document does not change that, and status reports it (installationId, repositorySelection, repoCount). metadata.name is the account lower-cased, with every run of characters other than a to z and 0 to 9 replaced by one hyphen: acme-platform for acme-platform, codeberg-org-acme for codeberg.org/acme. Applying also keeps the scope.orgs setting of the factory settings document in step. Deleting the document stops managing the account; the record is kept, so managing it again restores it.

## Applying this kind

- **Command.** `vulnetix config apply -f <file>`; the CLI line above says from which release. Plan first with [`vulnetix config plan`](/platform-iac/cli/plan/): it shows each object as create, update, delete or no change, with a `planHash` that apply then holds to. Apply writes in one transaction.
- **Manager.** Each object records the manager that applied it (`terraform`, `console` or `gitops:<repo>`). `--prune` deletes only objects its own manager owns. See [The manager](/platform-iac/cli/plan/#the-manager) and the [config engine](/platform-iac/reference/engine/).
- **Status.** `installationId`, `accountType`, `repositorySelection`, `repoCount` and `installationStatus`, read only. The phases the engine reports are explained under [status phases](/platform-iac/reference/engine/#status-phases).

## How apply treats it

- `metadata.name` is derived from `spec.account` (lower case, runs of other characters become one hyphen). A document whose name is not derived from its account is refused, because read finds the row by it.
- `spec.account` is the login (`host/account` for a forge connection), lower-cased. Plan needs the account to be connected and active.
- Apply writes the row, `scope.orgs` in the settings document, and a setting event. The status reports the installation id, account type, repository selection, repository count and installation status. Which repositories the GitHub App reaches stays on GitHub and is read only here.
- Delete switches management off. The row is kept.
