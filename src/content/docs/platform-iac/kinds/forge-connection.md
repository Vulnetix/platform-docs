How the Software Factory reaches a git forge other than github.com: a bot account's access token on Gitea, Forgejo or GitLab (or GitHub Enterprise Server), or a GitHub App registered on a GitHub Enterprise Server. github.com is reached through the Vulnetix GitHub App instead (GitHubInstallation). Apply asks the forge what it is and checks the credential can list repositories before anything is stored; the credential and the webhook secret are kept in the tenant's vault as a connector secret, never in the document, an export or a plan. The type, host and account identify the connection and cannot change: declare a new connection instead. Deleting the document removes the webhooks the factory created, revokes the stored credential and marks the connection deleted; managed scope and repository settings rows are kept, read-only, as for an uninstalled App.

# yaml-language-server: $schema=https://github.com/Vulnetix/config-schemas/releases/latest/download/ForgeConnection.schema.json
# A self-managed GitLab group reached with a bot token, with an OAuth
# application so members can link their own GitLab accounts, and a GitHub
# Enterprise Server reached through a GitHub App registered on it.
apiVersion: vulnetix.com/v1
kind: ForgeConnection
metadata:
  name: gitlab-platform
  labels:
    team: platform
  annotations:
    note: The bot account is vulnetix-bot, a Developer in the platform group.
spec:
  type: gitlab
  host: gitlab.example.com
  apiBase: https://gitlab.example.com/api/v4
  account: platform
  token: { env: VULNETIX_GITLAB_TOKEN }
  oauth:
    clientId: 6f1e2d3c4b5a69788796a5b4c3d2e1f0
    clientSecret: { env: VULNETIX_GITLAB_OAUTH_SECRET }
---
apiVersion: vulnetix.com/v1
kind: ForgeConnection
metadata:
  name: ghes-acme
spec:
  type: ghes
  host: github.acme.example
  account: acme
  app:
    appId: 12
    appSlug: vulnetix

## Applying this kind

- **Command.** `vulnetix config apply -f <file>`; the CLI line above says from which release. Plan first with [`vulnetix config plan`](/platform-iac/cli/plan/): it shows each object as create, update, delete or no change, with a `planHash` that apply then holds to. Apply writes in one transaction.
- **Manager.** Each object records the manager that applied it (`terraform`, `console` or `gitops:<repo>`). `--prune` deletes only objects its own manager owns. See [The manager](/platform-iac/cli/plan/#the-manager) and the [config engine](/platform-iac/reference/engine/).
- **Status.** `connection`, `botLogin` and `version`. The phases the engine reports are explained under [status phases](/platform-iac/reference/engine/#status-phases).

## How apply treats it

The Resolve Platform's create and update writers, now transaction scoped. A bot token or a GitHub Enterprise Server App key is a `valueFrom` secret, kept as the Resolve Platform keeps it. GitHub.com is refused: use [`GitHubInstallation`](/platform-iac/kinds/git-hub-installation/).
