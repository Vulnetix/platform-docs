A risk prioritisation strategy: an ordered list of rules that puts every open finding in a priority tier. A finding's tier is the position of the first rule it matches, 0 being the highest priority. A tenant may keep several strategies; one is active, and a tenant with none active uses the system default.

# yaml-language-server: $schema=https://github.com/Vulnetix/config-schemas/releases/latest/download/RiskStrategy.schema.json
apiVersion: vulnetix.com/v1
kind: RiskStrategy
metadata:
  name: exploit-first
  labels:
    team: platform-security
  annotations:
    ticket: https://jira.example.com/browse/SEC-2214
spec:
  description: Known exploitation first, then exposure, then score.
  active: true
  rules:
    - { metric: MALWARE, operator: IS_TRUE, label: Malware }
    - { metric: KEV_CISA, operator: IS_TRUE, label: CISA KEV }
    - { metric: EXPLOIT_WEAPONIZED, operator: IS_TRUE, enabled: true }
    - { metric: INTERNET_EXPOSED_PACKAGE, operator: IS_TRUE, label: Exposed package }
    - metric: ATTACK_PATH
      operator: IS_TRUE
      attackPathId: 0b9d5f9e-3c51-4a0f-9d43-6f1f5f0c2a11
      label: Edge to database
    - metric: CEL
      label: Reachable and likely
      when: reachable && (epss >= 0.2 || exploitMaturity == 'active')
    - { metric: EPSS, operator: GTE, thresholdLow: 0.1 }
    - { metric: CVSS, operator: BETWEEN, thresholdLow: 7, thresholdHigh: 10 }

## Rules

Conditions the schema enforces beyond each field's own type. `vulnetix config validate` and the engine's plan report a document that breaks one.

| On | Rule |
|---|---|
| `spec.rules[]` | When `metric` is one of `MALWARE`, `KEV_CISA`, `KEV_ENISA`, `KEV_VULNETIX`, `KEV_VULNCHECK`, `EXPLOIT_WEAPONIZED`, `EXPLOIT_ACTIVE`, `EXPLOIT_POC`, `INTERNET_EXPOSED_PACKAGE`, `INTERNET_EXPOSED`, `REACHABLE`, `UNREACHABLE`, `TRACEABLE`, `TRACEABLE_GRAPH`, `ATTACK_PATH`: `operator` is required and `operator` must be `IS_TRUE`. |
| `spec.rules[]` | When `metric` is one of `CVSS`, `CWSS`, `CUSTOM_CVSS`, `CUSTOM_CWSS`, `CESS`, `EPSS`: `operator` is required and `operator` must be `GTE`, `GT`, `LTE`, `LT`, `BETWEEN`, `ALWAYS`. |
| `spec.rules[]` | When `metric` is `REMAINING`: `operator` is required and `operator` must be `ALWAYS`. |

## CEL variables

`spec.rules[].when` is a CEL expression in the `finding` context, returning `bool`. It is evaluated by the ranking ladder in the Vulnetix site API, over the tenant's open findings (at most 5000, most severe first). **Fails open.** A rule that does not compile matches nothing and is logged. A finding the expression errors on does not match. See [where each expression is evaluated](/platform-iac/reference/cel/#where-each-expression-is-evaluated). The functions, limits and error codes are on [CEL rule expressions](/platform-iac/reference/cel/).

| `aliases` | `list(string)` | 64 items of 256 chars | Other identifiers the advisory is known by. |

## Applying this kind

- **Command.** `vulnetix config apply -f <file>`; the CLI line above says from which release. Plan first with [`vulnetix config plan`](/platform-iac/cli/plan/): it shows each object as create, update, delete or no change, with a `planHash` that apply then holds to. Apply writes in one transaction.
- **Manager.** Each object records the manager that applied it (`terraform`, `console` or `gitops:<repo>`). `--prune` deletes only objects its own manager owns. See [The manager](/platform-iac/cli/plan/#the-manager) and the [config engine](/platform-iac/reference/engine/).
- **Status.** Applied, Unchanged or Deleted, with no other status fields. The phases the engine reports are explained under [status phases](/platform-iac/reference/engine/#status-phases).

## How apply treats it

- Rules are diffed per item, so an unchanged rule keeps its row. The rules are stored in `RiskPrioritizationRule`.
- `spec.active: true` moves the one active strategy to this one and deactivates the others.
- A rule with `when` is stored with metric `CEL` and the expression in `RiskPrioritizationRule.expr`.
- The expression is type-checked at plan. It is evaluated by the ranking ladder; see [where each `when` runs](/platform-iac/reference/cel/#where-each-expression-is-evaluated).
