Entries for the tenant's package firewall allow list or deny list. The tenant has one of each; every PackageList contributes its entries to one of them, and owns only the entries it declares. A deny entry always blocks, in every mode, ahead of every other check. An allow entry waives every policy block (thresholds, KEV, exploits, bad actors, end of life, cooldown, version lag) but never an exact-version malware match, a known-bad artifact hash or a malware scan verdict.

metadata:
  name: first-party

    team: platform-security

  list: allow

## CEL variables

`spec.entries[].when` is a CEL expression in the `package` context, returning `bool`. It is evaluated by the package firewall proxy, for each requested version, in `evaluate()`. The entry is skipped and the proxy logs it. See [where each expression is evaluated](/platform-iac/reference/cel/#where-each-expression-is-evaluated). The functions, limits and error codes are on [CEL rule expressions](/platform-iac/reference/cel/).

| Variable | Type | Bound | Description |
|---|---|---|---|
| `purl` | `string` | 2048 chars | Package URL of the requested version. |
| `ecosystem` | `string` | 64 chars | Package ecosystem, such as `npm`, `pypi`, `golang`, `maven`. |
| `name` | `string` | 512 chars | Package name as the ecosystem writes it: `@acme/tool`, `github.com/acme/tool`, `com.acme:tool`. |
| `version` | `string` | 256 chars | Requested version. |
| `published` | `timestamp` |  | When the version was published. The zero timestamp when unknown. |
| `ageDays` | `int` |  | Derived. Whole days from `published` to `now`. -1 when the publish time is unknown, so a cooldown rule never reads an unknown age as new. |
| `versionLag` | `int` |  | How many releases are newer than this version. 0 for the newest, or when the lag is unknown. |
| `malware` | `bool` |  | The version is known malware. |
| `cvss` | `double` |  | Highest CVSS base score across the version's advisories. |
| `epss` | `double` |  | Highest EPSS probability across the version's advisories. |
| `cess` | `double` |  | Highest Coalition ESS score across the version's advisories. |

| `now` | `timestamp` |  | The time of evaluation. Callers may fix it; otherwise it is the clock when Eval runs. |

## Applying this kind

- **Command.** `vulnetix config apply -f <file>`; the CLI line above says from which release. Plan first with [`vulnetix config plan`](/platform-iac/cli/plan/): it shows each object as create, update, delete or no change, with a `planHash` that apply then holds to. Apply writes in one transaction.
- **Manager.** Each object records the manager that applied it (`terraform`, `console` or `gitops:<repo>`). `--prune` deletes only objects its own manager owns. See [The manager](/platform-iac/cli/plan/#the-manager) and the [config engine](/platform-iac/reference/engine/).
- **Order.** Applied after [`PackageFirewallPolicy`](/platform-iac/kinds/package-firewall-policy/), so a document that refers to one by `metadata.name` can be in the same apply. Deleted before them.
- **Status.** Applied, Unchanged or Deleted, with no other status fields. The phases the engine reports are explained under [status phases](/platform-iac/reference/engine/#status-phases).

## How apply treats it

- A `PackageList` owns only the entries it declares. Entries made in the console, and entries another `PackageList` declares, are never changed or pruned by it.
- Entries are compared one by one, keyed by ecosystem, package name and version as the purl maps to them.
- Every write appends a package firewall list audit row in the same transaction, with the same actions the console records (create, update, move, activate, delete). The actor is the applying principal and the manager.
- Applied after the [`PackageFirewallPolicy`](/platform-iac/kinds/package-firewall-policy/).

## Terraform and OpenTofu

The resource is `vulnetix_package_list` in the `vulnetix/vulnetix` provider. Its arguments are the `spec` in snake case, beside `name`, `labels` and `annotations` from `metadata`. The Minimal and Advanced HCL are above. The provider's own reference is [vulnetix_package_list](https://registry.terraform.io/providers/vulnetix/vulnetix/latest/docs/resources/package_list).
