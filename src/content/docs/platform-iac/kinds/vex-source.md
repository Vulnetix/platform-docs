VEX documents read back as suppression rules. A not_affected statement (CycloneDX not_affected or false_positive) becomes a suppression with the document's justification, timestamp and author; fixed or resolved marks the finding remediated; affected, in_triage and exploitable are recorded as triage context; under_investigation is an annotation. Products are matched to findings by purl. A later statement wins. Suppressions a source creates are owned by it: they go when the statement leaves the document, and cannot be deleted by hand. Name exactly one of tea, s3, git, path or urls.

How sources are fetched, how statements become suppressions and how a `path` source is uploaded are on [VEX documents as suppression rules](/platform-iac/guides/vex-sources/). The Advanced sample applies as written. The fields the schema accepts but plan blocks are listed under [what plan refuses](#what-plan-refuses-today), and the schema release carries them in `examples/VexSource/unsupported-features.yaml`.

## Rules

Conditions the schema enforces beyond each field's own type. `vulnetix config validate` and the engine's plan report a document that breaks one.

| On | Rule |
|---|---|
| `spec` | Exactly one of `tea`, `s3`, `git`, `path` or `urls` is set. |
| `spec.scope` | Exactly one of these holds: (1) `org` is required, `repos` is not allowed and `products` is not allowed; (2) `org` is not allowed and At least one of `repos` or `products` is set.. |
| `spec.refresh` | Exactly one of `interval` or `webhook` is set. |
| `spec.tea` | Exactly one of `product`, `productRelease` or `collection` is set. |
| `spec.s3` | When `endpoint` is set: `credentialRef` is required. Otherwise: `roleArn` is required and `credentialRef` is not allowed. |
| `spec.s3` | Exactly one of `prefix` or `key` is set. |

## Applying this kind

- **Command.** `vulnetix config apply -f <file>`; the CLI line above says from which release. Plan first with [`vulnetix config plan`](/platform-iac/cli/plan/): it shows each object as create, update, delete or no change, with a `planHash` that apply then holds to. Apply writes in one transaction.
- **Manager.** Each object records the manager that applied it (`terraform`, `console` or `gitops:<repo>`). `--prune` deletes only objects its own manager owns. See [The manager](/platform-iac/cli/plan/#the-manager) and the [config engine](/platform-iac/reference/engine/).
- **Order.** Applied after [`VaultEntry`](/platform-iac/kinds/vault-entry/), so a document that refers to one by `metadata.name` can be in the same apply. Deleted before them.
- **Status.** The latest fetch: status `ok`, `partial` or `error`, document, statement and suppression counts, and per-document errors. The phases the engine reports are explained under [status phases](/platform-iac/reference/engine/#status-phases).

## What plan refuses today

The schema accepts these, and plan blocks them with the condition `unsupported`:

| Field | Why |
|---|---|
| `spec.trust.requireSignature: true` | The server does not verify signatures on fetched VEX documents. Narrow trust with `trust.allowedAuthors` instead. |
| `spec.scope.products` | Findings do not record the TEA product they belong to, so the scope could not be enforced. Use `scope.repos`. |
| `spec.s3.endpoint` | An S3-compatible store is not supported yet. Use `roleArn` on AWS. |

A `path` source plans with the warning `cli_only`: the server never fetches it. The guide has [the rest](/platform-iac/guides/vex-sources/).

## Terraform and OpenTofu

The resource is `vulnetix_vex_source` in the `vulnetix/resolve` provider. Its arguments are the `spec` in snake case, beside `name`, `labels` and `annotations` from `metadata`. The Minimal and Advanced HCL are above. The provider's own reference is [vulnetix_vex_source](https://registry.terraform.io/providers/vulnetix/resolve/latest/docs/resources/vex_source).

Import an object that already exists by its name:

```shell
# Import an existing VexSource by its name (metadata.name).
terraform import vulnetix_vex_source.local_vex local-vex
```

Install, authentication and how state is read: [Terraform and OpenTofu](/platform-iac/terraform/).
