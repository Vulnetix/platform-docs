Which AWS-native sources and Vulnetix passes are read, for one account or for every account. The sources listed are turned on; every other source is turned off for that scope. Once a source is on, everything it reports is ingested: granularity stops at the source. Turning one off stops reading it and keeps the findings already ingested, with their triage history. Each source's consent record is a named inline policy on the execution role, attached by redeploying the stack, so set deploy to attach it in the same apply. Turning a source on needs a connected AWS account. Not stored yet for one account: CloudNativeSource.accountId exists and is keyed, but no route writes an account id and the stack deploy reads the sources for the whole tenant, so only account "*" applies today. A document naming an account validates, and applying it needs that write path and a per-account read in the deploy.

## Applying this kind

- **Command.** `vulnetix config apply -f <file>`; the CLI line above says from which release. Plan first with [`vulnetix config plan`](/platform-iac/cli/plan/): it shows each object as create, update, delete or no change, with a `planHash` that apply then holds to. Apply writes in one transaction.
- **Manager.** Each object records the manager that applied it (`terraform`, `console` or `gitops:<repo>`). `--prune` deletes only objects its own manager owns. See [The manager](/platform-iac/cli/plan/#the-manager) and the [config engine](/platform-iac/reference/engine/).
- **Order.** Applied after [`AwsConnection`](/platform-iac/kinds/aws-connection/) and [`AwsAccount`](/platform-iac/kinds/aws-account/), so a document that refers to one by `metadata.name` can be in the same apply. Deleted before them.
- **Status.** Applied, Unchanged or Deleted, with no other status fields. The phases the engine reports are explained under [status phases](/platform-iac/reference/engine/#status-phases).

## How apply treats it

- `account: "*"` is the choice for every account. An account id is an override for that account, which then reads exactly its own sources.
- Only the sources in the schema are written, and only rows whose state changes.
- `deploy: true` queues the stacks of the accounts the document covers (`"*"`: every enabled account without an override).
- Deleting an override sends the account back to `"*"`. Deleting `"*"` turns every source off.
- A per-account document needs saas migration `20261226020000_cloud_native_source_per_account`. Until it runs, plan blocks the document with the migration's name, and `"*"` works as before.
