A jail policy: the ordered rules vulnetix jail evaluates for a repository over everything ever reported for it (vulnerabilities past their SLA, dependencies past end of life, migrations that have not landed, hygiene categories that regressed). A policy without repository is the tenant's default; a policy with one is a per-repository override that replaces the default outright. Separate from QualityGate, which judges a single scan.

apiVersion: vulnetix.com/v1
kind: JailPolicy
metadata:
  name: payments-api
  labels:
    team: payments
  annotations:
    ticket: https://tracker.example.com/SEC-1980
spec:
  repository: acme/payments-api
  description: Payments ships with no overdue criticals, no live secrets, and moment.js on its way out.
  enabled: true
  enforcementMode: enforce
  defaultStalenessDays: 7
  onStale: fail
  rules:
    - kind: VULN
      label: No reachable critical npm finding past its SLA
      enabled: true
      category: SCA
      toolName: vulnetix
      ecosystem: npm
      severityFloor: critical
      flags: [reachable, hasFix]
      aggregate: COUNT_PAST_SLA
      operator: GT
      thresholdLow: 0
      onBreach: BLOCK
      stalenessDays: 3
      onStale: warn
      ratchet: false
      when: "fixAvailability == 'available' && (kev || epss >= 0.1)"
    - kind: GOAL
      label: Off moment.js
      targetPattern: pkg:npm/moment@*
      aggregate: COUNT
      operator: GT
      thresholdLow: 0
      deadline: 2027-03-31
      ratchet: true
      onBreach: WARN
    - kind: HYGIENE
      label: Secrets stay between 0 and 2
      category: SECRETS
      aggregate: COUNT
      operator: OUTSIDE

## Rules

| On | Rule |
|---|---|
| `spec.rules[]` | When `operator` is one of `BETWEEN`, `OUTSIDE`: `thresholdHigh` is required. |
| `spec.rules[]` | When `aggregate` is `COUNT_PAST_SLA`: `kind` must be `VULN`. |
| `spec.rules[]` | When `kind` is `GOAL`: `targetPattern` is required. Otherwise: `ratchet` must be `false` and `deadline` is not allowed. |

## CEL variables

`spec.rules[].when` is a CEL expression in the `finding` context, returning `bool`. It is evaluated by the jail evaluator in the VDB API, which `vulnetix jail` and `vulnetix scan --jail` call, and by the Software Factory gate node for its `COUNT` rules. In the VDB API a rule whose `when` does not compile, or uses a variable its rule kind lacks, is skipped with a warning, and a fact the expression errors on makes the rule `indeterminate` (`vulnetix jail` exits 3). In the factory gate the rule **fails closed**: it breaches, labelled "when could not be evaluated". See [where each expression is evaluated](/platform-iac/reference/cel/#where-each-expression-is-evaluated). The functions, limits and error codes are on [CEL rule expressions](/platform-iac/reference/cel/).

Jail evaluates `when` over the facts it already holds, and those do not carry every `finding` variable. A rule whose `when` names a variable its kind does not fill in is skipped with a warning when the jail gate runs, rather than counting against a zero value:

| Rule `kind` | Variables `when` may use |
|---|---|
| `VULN` | `id`, `severity`, `cvss`, `kev`, `malicious`, `reachable`, `fixAvailability`, `direct`, `purl`, `ecosystem`, `labels`, `owner`, `criticality`, `now` |
| `EOL` | `id`, `severity`, `eol`, `direct`, `purl`, `ecosystem`, `labels`, `owner`, `criticality`, `now` |
| `HYGIENE` | `id`, `severity`, `cvss`, `labels`, `owner`, `criticality`, `now` |
| `GOAL` | `id`, `labels`, `owner`, `criticality`, `now` |

> [!CAREFUL] `epss` is not available to jail rules
> The `org-default.yaml` example below, and the `when` in the Advanced one, use `epss >= 0.1` on a `VULN` rule. It type-checks, so plan accepts it, but jail facts have no EPSS, so the jail gate skips that rule with a warning. ## How apply treats it

- A policy is addressed by `metadata.name`. The header fields merge: a field the document leaves out keeps its value.
- `spec.repository` is the scope, so leaving it out means the tenant default.
- `spec.rules`, when present, is the whole ordered list. Rules are matched to stored rules by `label` and updated in place, which keeps each rule's id (exemptions and the assessment history cite it). A label the document drops is deleted, and renaming a label is a delete and a create. Labels must be unique within a policy.
- Plan runs the console's policy and rule validators, so a policy the console refuses cannot be applied as code. A `when` that does not compile is reported with its rule and position.
