Recorded, attributed exceptions to the licence policy: a licence exempted everywhere (blanket) or one package exempted, each with who approved it, why, and until when. An exempted finding is kept and badged, never dropped, and an expired exception stops applying and says so; the expiry date is inclusive. Two forms are valid. The repository file .vulnetix/license-exceptions.yaml, read by vulnetix license and scan --evaluate-licenses, keeps blanket and packages at the top level with no metadata. The config form puts them under spec, with metadata. The server does not store exceptions yet: the CLI validates the document and plan notes it, but apply sends nothing.

`blanket` exceptions are checked first and the first unexpired match wins; `packages` are checked after them. See [Licence policy](/sca/license/policy/) and [Licence evaluation](/sca/license/license/).

## Advanced

Every field the kind supports, with a `when` expression where it takes one. From `examples/LicenseExceptions/advanced.yaml`.

**YAML**

```yaml
# yaml-language-server: $schema=https://github.com/Vulnetix/config-schemas/releases/latest/download/LicenseExceptions.schema.json
apiVersion: vulnetix.com/v1
kind: LicenseExceptions
metadata:
  name: default
  labels:
    team: legal
  annotations:
    ticket: https://tracker.example.com/LEGAL-102
spec:
  blanket:
    - license: MPL-2.0
      id: LEX-001
      reason: File-level copyleft; we ship MPL files unmodified and publish their source.
      scope: unmodified
      approver: legal@acme.com
      approvedDate: "2026-03-02"
      expires: "2027-03-01"
      projects: ["*"]
  packages:
    - purl: pkg:golang/github.com/hashicorp/*
      license: BUSL-1.1
      id: LEX-002
      reason: Internal tooling only; not offered as a competing hosted service.
      scope: dynamically linked
      approver: legal@acme.com
      approvedDate: "2026-04-15"
      expires: "2026-12-31"
      projects: [infra-tools]
    - name: ghostscript
      license: AGPL-3.0-only
      id: LEX-003
      reason: Used in the batch PDF renderer, which is never exposed over a network.
      scope: vendored
      approver: cto@acme.com
      approvedDate: "2026-05-20"
      projects: [pdf-batch]
---
# The repository file form, .vulnetix/license-exceptions.yaml: blanket and packages at the top level, no metadata.
apiVersion: vulnetix.com/v1
kind: LicenseExceptions
blanket:
  - license: EPL-2.0
    reason: Eclipse libraries are used unmodified as build-time dependencies.
packages:
  - purl: pkg:npm/%40acme/internal-fonts
    reason: Proprietary fonts licensed to ACME under contract C-2291.
```

## Applying this kind

- **Not stored.** The engine registers the kind so that validate and plan check a document. A plan that includes one shows the warning `not_stored`, and apply sends nothing for it.

## Two forms

Both are valid, and a document is exactly one of them.

| Form | Where | Shape |
|---|---|---|
| Repository file | `.vulnetix/license-exceptions.yaml` | `blanket` and `packages` at the top level. `metadata` is optional. |
| Config | A document under `.vulnetix/config` | `metadata` and `spec` are required, and `blanket` and `packages` sit under `spec` |

The fields in the table are the same in both. A licence file written before documents carried `apiVersion` and `kind` is read as this kind from its well-known path, so an older repository keeps working. `vulnetix license` and `vulnetix scan --evaluate-licenses` read the file, or the document under `.vulnetix/config`, unless `--exceptions-file` names one. Defining it in both places, or twice, is an error. See [Which files are Platform IaC documents](/platform-iac/cli/validate/#which-files-are-platform-iac-documents). In GitHub Actions the [license action](/sca/github-actions/license/) reads the same files.

# The repository file form, .vulnetix/license-exceptions.yaml

## Where it takes effect

Like [`LicensePolicy`](/platform-iac/kinds/license-policy/), the server stores nothing for this kind. The engine registers it so that validate and plan check a document, and a plan that includes one shows the warning `not_stored`. The CLI reads the repository file on the machine running the scan.
