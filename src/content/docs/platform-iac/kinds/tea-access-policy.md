Who may read one published TEA object: a product, a component or a release's collection. This is the Vulnetix publication overlay's access policy; the TEA consumption API itself does not say who may fetch what. The policy in force for any object is the narrowest one declared anywhere from the object up to its product, so a private product keeps everything beneath it private whatever those objects declare, and widening the product back restores each one to its own declaration. Plan refuses a policy wider than the one its parent enforces. An object no policy covers is private. Removing the document removes the declaration, and the object inherits from its parent again; for a product or component that means private. Mirroring to other TEA servers (publishTo in the publisher API) is not part of this kind, because this server does not mirror yet.

## Applying this kind

- **Command.** Not yet. The latest CLI, v3.166.0, embeds `config-schemas` v1.3.0, which has no `TeaAccessPolicy`, so `vulnetix config` refuses the document as an unknown kind before sending it. Use the config API, or Terraform where the kind has a resource, until a CLI release embeds it. Plan first with [`vulnetix config plan`](/platform-iac/cli/plan/): it shows each object as create, update, delete or no change, with a `planHash` that apply then holds to. Apply writes in one transaction.
- **Manager.** Each object records the manager that applied it (`terraform`, `console` or `gitops:<repo>`). `--prune` deletes only objects its own manager owns. See [The manager](/platform-iac/cli/plan/#the-manager) and the [config engine](/platform-iac/reference/engine/).
- **Order.** Applied after [`TeaProduct`](/platform-iac/kinds/tea-product/), [`TeaComponent`](/platform-iac/kinds/tea-component/) and [`TeaCollection`](/platform-iac/kinds/tea-collection/), so a document that refers to one by `metadata.name` can be in the same apply. Deleted before them.
- **Status.** Applied, Unchanged or Deleted, with no other status fields. The phases the engine reports are explained under [status phases](/platform-iac/reference/engine/#status-phases).

## How apply treats it

Set as the publisher API sets it, refusing a policy wider than its parent enforces. Grants are replaced.
