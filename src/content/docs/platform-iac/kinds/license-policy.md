A licence policy: which licence categories produce findings and at what severity, how unresolved licences and dependency scopes are treated, and per-project overrides. Two forms are valid. The repository file .vulnetix/license-policy.yaml, read by vulnetix license and scan --evaluate-licenses, keeps the policy fields at the top level with no metadata; this is what vulnetix license policy init writes. The config form puts the same fields under spec, with metadata. Absent sections inherit the defaults: unknown is warn, no scope is ignored, and only strong-copyleft (high) and unknown (medium) carry a severity.

- **Not stored.** The engine registers the kind so that validate and plan check a document. A plan that includes one shows the warning `not_stored`, and apply sends nothing for it.

## Where it takes effect

The server does not store this kind. `vulnetix license` and `vulnetix scan --evaluate-licenses` read the repository file `.vulnetix/license-policy.yaml` on the machine running the scan. The engine registers the kind only so that validate and plan check a document against the schema: a plan that includes one shows the warning `not_stored` instead of refusing the set as an unknown kind. Commit the policy to `.vulnetix/license-policy.yaml` in each repository.
