A Guardian alert rule: a detection run on a schedule over the tenant's logs, raising alerts. Name exactly one of body, file, searchRef, countermeasure, sigmahq or ioc. body and file are the tenant's own rule; the others run a rule Guardian already has, which can be tuned (level, threshold, suppressions, timing) but not edited. A rule whose detection does not compile, or names a log source Guardian has no table for, is stored turned off. The plan caps how many rules run at once. Deleting one that an AlertTrigger still uses is refused.

## Applying this kind

- **Command.** `vulnetix config apply -f <file>`; the CLI line above says from which release. Plan first with [`vulnetix config plan`](/platform-iac/cli/plan/): it shows each object as create, update, delete or no change, with a `planHash` that apply then holds to. Apply writes in one transaction, except for the second phase below.
- **Manager.** Each object records the manager that applied it (`terraform`, `console` or `gitops:<repo>`). `--prune` deletes only objects its own manager owns. See [The manager](/platform-iac/cli/plan/#the-manager) and the [config engine](/platform-iac/reference/engine/).
- **Order.** Applied after [`SavedSearch`](/platform-iac/kinds/saved-search/) and [`MessagingConnection`](/platform-iac/kinds/messaging-connection/), so a document that refers to one by `metadata.name` can be in the same apply. Deleted before them.
- **Second phase.** This kind is not written inside the apply transaction. The other kinds apply and commit first, then each DetectionRule is written on its own, in Guardian. One that fails reports `status.phase: Failed` and a `message`, and nothing is recorded for it. The others stay applied and the apply answers 207. Plan again to see what is left. A single `PUT` from the Terraform provider answers 502 `external_failed` instead.
- **Status.** A failed second-phase write reports phase `Failed` with a `message`. The phases the engine reports are explained under [status phases](/platform-iac/reference/engine/#status-phases).

## How apply treats it

Written in Guardian, in the second phase; see [SIEM kinds](/platform-iac/reference/engine/#siem-kinds-written-in-guardian).

- Levers, threshold, target, suppressions, level, display name and a Sigma `body` change in place.
- The source (`searchRef`, `countermeasure`, `sigmahq`, `ioc`, or a body versus another form) cannot move. The plan blocks it: declare the new rule under a new name.
- `sigmahq` is resolved by path through Guardian's catalogue.
- `file` is refused, because the server never reads a path. Send the text as `body`.
- A `dsl` body is refused, because Guardian keeps a DSL rule only as a copy of a saved search. Use `searchRef`.
- A rule Guardian cannot compile stays off whatever `enabled` says, so `enabled` is not a change for it and the plan warns with the compile error.
- `displayName` and `level` default to Guardian's choice, so they are compared only when the document sets them.
