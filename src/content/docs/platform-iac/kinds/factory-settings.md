The Software Factory settings document: the tenant-wide factory settings the console's Settings page edits. One per tenant. Each field is one setting, and its dotted path (autonomy.max) is the key the console, the API and the audit trail name it by. A field left out means the setting's default, so applying a document resets every setting it does not name, and an export lists only the settings that differ from their defaults. Applying saves a new revision of the document through the console's own writer, with one audit entry per changed setting; status.revision is the revision saved. The security scanner settings are the ScannerProfile document, the managed organisations are FactoryManagedOrg documents and the web push defaults (notify.push.defaults) are the NotificationDefaults document, so none of them appears here. Read-only settings (forge.polling.forbidden, firewall_enabled, systemone.min_confidence.adapter) are not part of the document.

## Fields

Paths use dots for nesting and `[]` for the items of a list. **Required** means required whenever the parent object is present. A default is what the server uses when the field is left out.

| Field | Type | Required | Default | Allowed values | Description |
|---|---|---|---|---|---|
| <span id="apiVersion"></span>`apiVersion` | string | yes |  | exactly `vulnetix.com/v1` | The document format version. Every kind in this release is vulnetix.com/v1. |
| <span id="kind"></span>`kind` | string | yes |  | exactly `FactorySettings` | Always FactorySettings. |
| <span id="metadata"></span>`metadata` | object | yes |  | no other keys | Metadata for a kind the tenant has exactly one of. The name is fixed to default. |
| <span id="metadata-name"></span>`metadata.name` | string | yes |  | exactly `default`; pattern `^[a-z0-9]([a-z0-9-]{0,61}[a-z0-9])?$` | The object's name, unique per kind within a tenant. It is the natural key: plan, apply, export and the Terraform provider all address an object by kind and name. |
| <span id="metadata-org"></span>`metadata.org` | string | no |  | format `uuid` | The tenant (organization UUID) the document belongs to. When set, plan and apply refuse to run against any other tenant. |
| <span id="metadata-labels"></span>`metadata.labels` | object | no |  | map of string to string (length 0 to 256); keys match `^[a-z0-9]([a-z0-9._/-]{0,61}[a-z0-9])?$` | Free key/value labels. Stored with the object, never interpreted by the server. |
| <span id="metadata-annotations"></span>`metadata.annotations` | object | no |  | map of string to string (length 0 to 4096) | Free key/value notes for people and tools, such as a ticket link. |

## Applying this kind

- **Command.** `vulnetix config apply -f <file>`; the CLI line above says from which release. Plan first with [`vulnetix config plan`](/platform-iac/cli/plan/): it shows each object as create, update, delete or no change, with a `planHash` that apply then holds to. Apply writes in one transaction.
- **Manager.** Each object records the manager that applied it (`terraform`, `console` or `gitops:<repo>`). `--prune` deletes only objects its own manager owns. See [The manager](/platform-iac/cli/plan/#the-manager) and the [config engine](/platform-iac/reference/engine/).
- **Status.** `revision`. The phases the engine reports are explained under [status phases](/platform-iac/reference/engine/#status-phases).
- **Singleton.** There is one per tenant, and its name is always `default`.

## How apply treats it

- A singleton. Every writable key of the factory settings table is a nested field (`autonomy.max` is `spec.autonomy.max`), except the keys other kinds own and the read-only keys (`forge.polling.forbidden`, `firewall_enabled`, `systemone.min_confidence.adapter`).
- Replace semantics: a field left out is the default. Read returns only the settings that differ from the default, so exports are compact.
- Validation is the console's key table. Plan runs the read-only cross-key rules, including the `forge.check_runs` permission.
- Apply writes through the same function as the settings page: a revision bump, the write-through hooks such as the tenant Factory budget, and one setting event and audit entry per changed key. The status reports `revision`.
- Delete resets its keys to the defaults. The document stays.

### Which kind owns which key

[`ScannerProfile`](/platform-iac/kinds/scanner-profile/) owns the four `security.*` scanner keys, [`FactoryManagedOrg`](/platform-iac/kinds/factory-managed-org/) owns `scope.orgs`, [`NotificationDefaults`](/platform-iac/kinds/notification-defaults/) owns `notify.push.defaults`, and `FactorySettings` owns the rest. A `FactorySettings` apply never writes a key it does not own, so the kinds cannot undo each other.

> [!CAREFUL] Not everything the console does after a save happens
> The post-commit nudges the console save sends (seeding the default workflows when `defaults.enabled` changes, engine state and budget nudges, and the work after managing an organization) are not sent after an engine apply. The scheduler and the next event pick the changes up.

### Export and import of the settings page

`GET /v1/factory/settings?format=yaml|hcl|sh` renders the `FactorySettings`, `ScannerProfile` and `FactoryManagedOrg` documents with the engine's export. `PUT /v1/factory/settings` with `Content-Type: application/yaml` takes either these documents or the old flat export (read-only keys dropped, `github.*` renamed, the `scope.orgs` list turned into `FactoryManagedOrg` documents), then plans and applies them as manager `console`. `?dryRun=true` returns the plan.

## Terraform and OpenTofu

The resource is `vulnetix_factory_settings` in the `vulnetix/resolve` provider. Its arguments are the `spec` in snake case, beside `name`, `labels` and `annotations` from `metadata`. The Minimal and Advanced HCL are above. The provider's own reference is [vulnetix_factory_settings](https://registry.terraform.io/providers/vulnetix/resolve/latest/docs/resources/factory_settings).

Import an object that already exists by its name (`default`):

```shell
# Import an existing FactorySettings by its name (metadata.name).
terraform import vulnetix_factory_settings.default default
```
