The configuration runtime sensors enroll with and keep pulling: mode, hold, rule feeds, forwarding and tamper protection, and which people or MDM systems it applies to. It is a sensor provisioning profile. A device takes the enabled profile with the highest priority that matches it, and picks up a change on its next config pull. Sensors configured by hand with an ApiKey do not read profiles; a person changes their mode from the console. A profile with enrolled devices cannot be deleted.

## Applying this kind

- **Command.** `vulnetix config apply -f <file>`; the CLI line above says from which release. Plan first with [`vulnetix config plan`](/platform-iac/cli/plan/): it shows each object as create, update, delete or no change, with a `planHash` that apply then holds to. Apply writes in one transaction.
- **Manager.** Each object records the manager that applied it (`terraform`, `console` or `gitops:<repo>`). `--prune` deletes only objects its own manager owns. See [The manager](/platform-iac/cli/plan/#the-manager) and the [config engine](/platform-iac/reference/engine/).
- **Order.** Applied after [`DetectionRuleFeed`](/platform-iac/kinds/detection-rule-feed/), so a document that refers to one by `metadata.name` can be in the same apply. Deleted before them.
- **Status.** Applied, Unchanged or Deleted, with no other status fields. The phases the engine reports are explained under [status phases](/platform-iac/reference/engine/#status-phases).

## How apply treats it

- This is a [provisioning profile](/virtual-patching/sensor/provisioning-profiles/) as code. `metadata.name` is the profile name.
- The console's normalisation and feed reference checks run on every document, so a document is refused where the provisioning form is.
- `feeds` items are one of: `feedRef` (a [`DetectionRuleFeed`](/platform-iac/kinds/detection-rule-feed/), stored as its `https://vulnetix.com/feeds/<org>/<feed>` URL, which must be published when the policy is applied; a feed in the same apply is published first), `sensorFeed` (an indicator feed, stored as `org:<uuid>`), or an https URL (a published Vulnetix rule feed or a catalogue feed, stored as `catalog:<id>`). Read renders each stored reference back in that order. Left out, `feeds` are the catalogue defaults, as for a console-created profile.
- A profile with enrolled, unrevoked devices cannot be deleted or pruned. Plan blocks it and names the count.
