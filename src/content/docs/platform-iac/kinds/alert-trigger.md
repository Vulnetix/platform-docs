A Guardian trigger: run a SavedSearch or a DetectionRule on a schedule and, when its rows pass the levers, start a Software Factory workflow, post to messaging connections or send an email, with the rows as context. No rows, nothing starts. Name exactly one of searchRef or ruleRef. The plan caps how many triggers are enabled at once.

## Rules

Conditions the schema enforces beyond each field's own type. `vulnetix config validate` and the engine's plan report a document that breaks one.

| On | Rule |
|---|---|
| `spec` | Exactly one of `searchRef` or `ruleRef` is set. |
| `spec.destination` | When `kind` is `messaging`: `connections` is required and `emails` is not allowed. |
| `spec.destination` | When `kind` is `email`: `emails` is required and `connections` is not allowed. |
| `spec.destination` | When `kind` is `workflow`: `connections` is not allowed and `emails` is not allowed. |

## Applying this kind

- **Command.** `vulnetix config apply -f <file>`; the CLI line above says from which release. Plan first with [`vulnetix config plan`](/platform-iac/cli/plan/): it shows each object as create, update, delete or no change, with a `planHash` that apply then holds to. Apply writes in one transaction, except for the second phase below.
- **Manager.** Each object records the manager that applied it (`terraform`, `console` or `gitops:<repo>`). `--prune` deletes only objects its own manager owns. See [The manager](/platform-iac/cli/plan/#the-manager) and the [config engine](/platform-iac/reference/engine/).
- **Order.** Applied after [`SavedSearch`](/platform-iac/kinds/saved-search/), [`DetectionRule`](/platform-iac/kinds/detection-rule/) and [`MessagingConnection`](/platform-iac/kinds/messaging-connection/), so a document that refers to one by `metadata.name` can be in the same apply. Deleted before them.
- **Second phase.** This kind is not written inside the apply transaction. The other kinds apply and commit first, then each AlertTrigger is written on its own, in Guardian. One that fails reports `status.phase: Failed` and a `message`, and nothing is recorded for it. The others stay applied and the apply answers 207. Plan again to see what is left. A single `PUT` from the Terraform provider answers 502 `external_failed` instead.
- **Status.** A failed second-phase write reports phase `Failed` with a `message`. The phases the engine reports are explained under [status phases](/platform-iac/reference/engine/#status-phases).

## How apply treats it

Written in Guardian, in the second phase; see [SIEM kinds](/platform-iac/reference/engine/#siem-kinds-written-in-guardian). Everything can change in place, including the source.
