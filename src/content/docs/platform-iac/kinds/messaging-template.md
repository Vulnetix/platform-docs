An organisation's own message template, which a MessagingRoute uses instead of the system template for the event type. One template renders for every provider: Slack, Teams, Discord and Google Chat get the title, summary, body, fields, actions and accent; Jira and GitHub Issues get the issue fields; a signed webhook gets the rendered text and, when asked, the event payload. Every text field is a Go text/template run in a sandbox: only the messaging functions are allowed, every value is escaped, and sizes are capped. Plan compiles each field and refuses a template with errors. Every change to content is saved as a new version, noted as applied as code, as a console edit is; earlier versions stay in the template's history. Deleting it is refused while a route outside this apply still uses it.

## Advanced

Every field the kind supports, with a `when` expression where it takes one. From `examples/MessagingTemplate/advanced.yaml`.

**YAML**

```yaml
# yaml-language-server: $schema=https://github.com/Vulnetix/config-schemas/releases/latest/download/MessagingTemplate.schema.json
apiVersion: vulnetix.com/v1
kind: MessagingTemplate
metadata:
  name: security-findings
  labels:
    team: security
  annotations:
    owner: appsec@acme.example
spec:
  displayName: Security findings
  description: Scan results for the security channel, with a link back to the scan.
  eventScope:
    - scan.completed
    - scan.build_broken
  baseSystemTemplate: generic
  content:
    title: "{{.event.title}}"
    summary: "{{with .subject.label}}{{.}}{{end}}"
    body: "{{range $k, $v := .data}}- **{{$k}}:** {{truncate 200 $v}}\n{{end}}{{with .mentions}}\n{{mentions .}}{{end}}"
    fields:
      - label: Severity
        value: "{{severityEmoji .event.severity}} {{severityLabel .event.severity}}"
        inline: true
    actions:
      - label: Open in Vulnetix
        url: "{{.event.url}}"
    accent: "{{.event.severity}}"
    issue:
      title: "[Vulnetix] {{.event.title}}"
      body: "{{.event.title}}"
      labels:
        - vulnetix
        - security
    digest:
      title: "{{.digest.count}} {{plural .digest.count \"event\" \"events\"}}"
      item: "{{.event.title}}{{with .subject.label}}: {{.}}{{end}}"
    webhook:
      includePayload: true
```

## Applying this kind

- **Command.** `vulnetix config apply -f <file>`; the CLI line above says from which release. Plan first with [`vulnetix config plan`](/platform-iac/cli/plan/): it shows each object as create, update, delete or no change, with a `planHash` that apply then holds to. Apply writes in one transaction.
- **Manager.** Each object records the manager that applied it (`terraform`, `console` or `gitops:<repo>`). `--prune` deletes only objects its own manager owns. See [The manager](/platform-iac/cli/plan/#the-manager) and the [config engine](/platform-iac/reference/engine/).
- **Status.** Applied, Unchanged or Deleted, with no other status fields. The phases the engine reports are explained under [status phases](/platform-iac/reference/engine/#status-phases).

## How apply treats it

The template is compiled at plan with the messaging centre's template compiler, so an error shows before anything is written. Every change saves a new version.
